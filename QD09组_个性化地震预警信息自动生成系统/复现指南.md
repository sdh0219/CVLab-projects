# 第一部分 · 项目导览

## 1.1 这个项目是做什么的

**一句话**：一个网页系统——用户填上自己的"身份/年龄/位置/行动能力"，选一条真实地震事件，系统按**规则引擎 + 震级分级 + 球面距离计算**，自动生成一段"千人千面"的地震预警文案，并附带地震统计仪表盘。

例子：同一场 M4.4 地震，系统对"78 岁、行动需协助的老人"会说"您属于老年重点关注人群，请等待社区网格员上门协助转移"；对"应急人员"会说"请立即到岗，关注次生灾害排查任务"。**同一份震情数据，不同的责任和行动建议**——这就是"个性化"的价值。

数据是真实的：系统内置 200 条 USGS（美国地质调查局）中国及周边地震事件（2025-12 至 2026-06，M2.5+），另有可选的联网爬虫从 USGS API 拉取最新地震。

## 1.2 先看成品（不用动手，双击打开就行）

| 位置 | 看什么 |
|---|---|
| `源码\static\charts\` 的 4 张 png | 地震统计仪表盘的图：震级分布、深度分布、时间趋势、经纬度散点 |
| `源码\static\` 的手机示意图 png | 预警文案在手机上呈现的样子 |

跑起来之后的页面（复现手册 2.6 有截图位置说明）：首页是"预警生成器"表单，`/dashboard` 是统计仪表盘。

## 1.3 输入与输出

**吃进去（输入）**：
- `源码\data\processed\earthquake_events_processed.csv`：200 条真实地震事件（时间/经纬度/深度/震级/位置描述，随项目附带，开箱即用）；
- 用户在网页表单填的：身份（普通居民/游客/应急人员/学生/老人…）、年龄、位置（可以是"纬度 经度"数字）、选择的地震事件、行动能力（正常/较弱/需协助）。

**吐出来（输出）**：
- 网页上的一段**个性化预警文案**（JSON 返回，前端渲染）：预警正文、风险等级（蓝/黄/橙/红）、需求类型、画像标签、行动建议、距震中距离；
- 统计仪表盘页面（4 张图 + 统计卡片）。

## 1.4 业务流程图

```
USGS 地震数据（内置 200 条 / 可联网更新）
        │
        ▼
用户在网页填画像：身份 + 年龄 + 位置 + 行动能力 + 选择地震事件
        │
        ▼
规则引擎三步走：
  ① 震级分级：<3 蓝 / <4.5 黄 / <6 橙 / ≥6 红
  ② Haversine 球面距离：用户坐标 vs 震中 → <50km 较近 / <200km 有影响 / ≥200km 影响小
  ③ 画像匹配：年龄+身份+行动能力 → 人群标签 + 重点需求 + 行动建议
        │
        ▼
模板拼装成预警文案 → 网页展示
（另有一条独立支线：Flask 仪表盘页展示地震统计图）
```

## 1.5 用到哪些技术（人话版）

| 技术名词 | 人话解释 |
|---|---|
| Flask | Python 的轻量网页框架：接收浏览器请求、返回网页/数据 |
| 前端/后端 | 浏览器里跑的页面 / 服务器上跑的程序，通过 HTTP 对话 |
| 路由（route） | URL 和处理函数的对应表，如 `/generate` 专门处理生成请求 |
| AJAX / fetch | 网页不发整体刷新、只偷偷交换一小段数据的技术 |
| 规则引擎 | 一堆 if-else 把业务知识写死在代码里——可解释、可审计 |
| Haversine 公式 | 按地球是球体算两点间大圆距离（R=6371km） |
| 爬虫（crawler） | 程序自动访问 API/网页抓数据 |
| matplotlib | 画统计图的 Python 库 |

## 1.6 做完这个项目，你将学会什么

- 理解**前后端分工**：表单怎么变成请求、后端怎么返回 JSON、前端怎么渲染——Web 开发的最小完整样本；
- 会跑一个 Flask 网站并理解路由、模板、表单三个概念；
- 学会地理距离计算（Haversine）和等级规则设计；
- 见识一个**健壮爬虫**的工程细节：重试、快照留存、失败回退缓存、"绝不造假数据"；
- 思考"规则生成 vs 大模型生成"预警文案的优劣（本项目是规则版，可与 LLM 版对比）。

# 第三部分 · 理解手册

## 3.1 背景：预警的"最后一公里"

地震预警系统（如中国的 IEEW）能在震后几秒到几十秒发出警报，但**警报内容对所有人是一样的**："XX 地发生 M6.0 地震"。老人看不懂要做什么、游客不知道往哪跑、应急人员需要的是任务指令。

这个项目回答的问题是：**同样的震情，能不能按"你是谁、你在哪、你能做什么"生成不同的行动指令？** 它用的是最朴素的方法——规则引擎（一大堆 if-else）。别小看 if-else：它每一条判断都能解释、能审计、能按政策随时修改——这在公共安全场景里比"大模型自由发挥"更可靠。（进阶思考：把两者结合——规则定边界，LLM 润色语言——是当前工业界主流做法。）

## 3.2 核心概念逐个讲

### 3.2.1 Flask 三种路由协作

- **页面路由** `render_template`：访问 `/` 返回整个 HTML 页面；
- **AJAX GET** `/get_event_detail`：前端选完地震下拉框，偷偷来问这条地震的详情（不刷新页面）；
- **表单 POST** `/generate`：接收画像表单，返回 JSON（预警文案），前端 JS 把它渲染出来。

这一套"页面 + 局部数据交换"就是现代网页的基本工作方式。

### 3.2.2 画像规则引擎（code/user_profile.py + warning_rules.py）

三个维度组合出人群标签：**年龄**（≥65 老年重点关注 / ≤18 未成年人 / 其他）、**身份**（游客/应急人员/普通居民…）、**行动能力**（需协助 → 优先协助人群）。每种人群对应一组"重点需求类型"和"行动建议"文本。纯规则、零随机——同样输入永远同样输出，公共系统要的就是这种确定性。

### 3.2.3 震级分级与 Haversine 距离

- 分级：M<3 蓝色提示 / <4.5 黄色注意 / <6 橙色预警 / ≥6 红色警报（`warning_rules.py`）；
- 距离：用户在"位置"里填的两个数字（正则抽取）与震中做 Haversine 球面距离：`d = 2R·arcsin√(sin²Δφ/2 + cosφ1·cosφ2·sin²Δλ/2)`，R=6371km。<50km "较近"、<200km "有影响"、≥200km "影响小"。**地理位置计算的最经典入门公式**。

### 3.2.4 健壮爬虫的四个工程细节（crawler/）

1. **重试**：失败重试 3 次，间隔 2 秒；
2. **快照留存**：每次抓到的原始 JSON 存档（`source_snapshot\`），可追溯；
3. **回退缓存**：网络失败时用本地缓存继续跑，系统不瘫痪；
4. **数据伦理**：抓不到就明确失败，**绝不编造假数据**（代码里有显式的 `Cannot generate fake data. Aborting.`）。

这四条是所有生产级数据管道的底线，值得背下来。

## 3.3 代码精讲

| 文件 | 行数不多，按这个顺序读 |
|---|---|
| `app.py` | 路由表：`/`（首页）、`/generate`（POST 生成）、`/dashboard`（仪表盘） |
| `code/warning_rules.py` | ① 震级四级分类函数 → ② Haversine → ③ 距离分档 |

## 3.4 动手改一改

**练习 1（入门）· 加一种新身份**
- 改哪：`code/user_profile.py` 里加"医护人员"分支，`templates/index.html` 下拉框加选项。
- 预期：选"医护人员"生成的文案带你自己写的建议。
- 学到：规则引擎怎么扩展——加分支不用动架构。

**练习 2（入门）· 调整震级分级阈值**
- 改哪：`warning_rules.py` 把橙色阈值从 6.0 改成 5.0。
- 预期：M5.2 的地震从黄色变橙色。
- 学到：政策参数如何影响系统输出。

**练习 3（进阶）· 提升距离精度提示**
- 改哪：在 `/generate` 里把"距离 XX 公里"改成同时给出"预计地震波到达时间"（距离 ÷ 约 3.5 km/s，S 波粗估）。
- 学到：把领域知识（波速）变成产品功能。

**练习 4（挑战）· 批量生成**
- 改哪：写个循环对 200 条地震各生成一次"老年人版"预警，统计红色/橙色占比。
- 学到：把交互功能变成批量分析——工程里常见的"反向使用"。

## 3.5 怎么读结果

生成的预警 JSON 包含：`warning_text`（完整文案）、`risk_label`（蓝/黄/橙/红）、`profile_label`（人群标签）、`need_type`（重点需求）、`distance_info`（距离提示）、`action_suggestion`（行动建议）。**判断系统是否"个性化"：固定地震事件，只改身份/年龄，diff 两次输出的 warning_text**——不同的部分就是个性化逻辑的产出。

## 3.6 思考题

1. 为什么预警文案用规则生成而不是让大模型自由写？什么场景下应该反过来？
2. 位置解析依赖用户正确填"纬度 经度"，填反了会怎样？怎么加校验？
3. 爬虫回退缓存意味着用户可能看到旧数据。产品设计上该怎么提示用户"数据截至 X 日"？
4. 把距离档位 50/200km 改成 30/150km，受影响最大的是哪类用户？
