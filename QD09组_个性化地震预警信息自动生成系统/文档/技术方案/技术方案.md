# 基于真实地震数据的个性化地震预警信息自动生成系统技术方案

**"AI+防灾减灾"学生实践项目09**


## 1 项目任务与需求分析

### 1.1 第九个项目要求

项目09的核心要求是构建一个个性化预警信息自动生成系统，涵盖以下要素：

- **不同用户类型**：系统应能区分不同身份的用户；
- **地理位置**：考虑用户所在位置对预警内容的影响；
- **灾害类型**：指定灾害类型；
- **风险等级**：根据灾害严重程度生成对应等级；
- **预警文本样例**：提供预警文本示例；
- **用户画像**：根据用户特征自动归类；
- **提示词模板**：使用模板生成文本；
- **文本生成**：自动生成预警文本；
- **个性化预警展示**：通过页面展示预警结果。

### 1.2 本项目对题目要求的实现

| 老师要求 | 当前项目实际实现 |
|----------|-----------------|
| 用户类型 | 普通居民、游客、应急人员，并结合年龄自动识别未成年人和老年人 |
| 地理位置 | 手动输入位置或使用浏览器 Geolocation API 一键定位 |
| 灾害类型 | 聚焦地震单灾种 |
| 风险等级 | 根据真实地震震级自动计算课程演示等级 |
| 用户画像 | 根据身份、年龄和行动能力自动生成用户画像标签 |
| 重点需求 | 系统自动推断，不依赖用户手动选择 |
| 文本生成 | 使用规则模板生成个性化地震应急提醒 |
| 页面展示 | Flask 页面呈现 + 手机预警弹窗模拟 |
| 数据展示 | Dashboard 页面展示四张真实地震数据统计图 |

### 1.3 系统功能需求

1. **真实地震数据网络采集**：从 USGS 官方接口自动采集最新地震目录数据；
2. **数据清洗与保存**：对原始数据进行格式统一、去重和缺失值处理；
3. **真实地震事件选择**：用户从下拉框中选择一条真实地震事件；
4. **用户信息输入**：支持输入人员身份、年龄、位置、行动能力；
5. **自动识别用户画像**：根据输入自动生成用户所属人群标签；
6. **自动判断重点需求**：根据画像自动推断用户最需要的应急内容；
7. **生成个性化提醒**：综合事件信息和用户画像生成差异化应急文本；
8. **展示地震事件详情**：选择事件后自动显示时间、震级、深度、位置等参数；
9. **展示统计图表**：Dashboard 页面展示震级分布、深度分布、时间趋势、地理散点四张图；
10. **支持离线缓存**：网络失败时使用上一次成功采集的真实数据；
11. **支持一键环境检测和启动**：提供批处理脚本方便运行。

### 1.4 非功能需求

- **可复现**：同一套代码和数据可在不同电脑上得到一致结果；
- **数据可追溯**：每条地震数据均可追溯到 USGS 官方原始记录；
- **页面易操作**：界面简洁，无需编程知识即可使用；
- **规则可解释**：每条生成结果都能追溯到对应的判断规则；
- **不生成假数据**：网络失败时不编造地震记录；
- **提示清晰**：系统在页面各关键位置提示免责声明和操作说明；
- **适合课堂演示**：一键启动，展示流程完整。

## 2 真实数据来源与采集方案

### 2.1 数据来源

本系统使用的地震事件数据来源于 **USGS（美国地质调查局）官方地震目录**，通过其 FDSN Event Web Service 公开接口获取。

| 项目 | 说明 |
|------|------|
| 数据源名称 | USGS Earthquake Catalog |
| 接口 URL | https://earthquake.usgs.gov/fdsnws/event/1/query |
| 数据格式 | GeoJSON |
| 查询区域 | 中国及周边区域（中心点纬度 35°N，经度 105°E） |
| 搜索半径 | 2000 公里 |
| 震级下限 | 2.5 级 |
| 时间范围 | 最近 180 天 |
| 单次最大返回数 | 200 条 |
| 排序方式 | 时间倒序 |

根据实际 `source_metadata.json` 和 `crawl_log.txt` 的记录，系统成功从 USGS 采集了 **200 条**真实地震记录。

系统还尝试了采集中国地震台网（CEIC）的数据，但由于页面反爬机制或网站结构变更，暂无法稳定获取数据。在日志和页面中，系统如实记录了 CEIC 采集失败的情况，不编造数据集。

### 2.2 网络采集方法

采集流程如下：

```
发送 HTTP GET 请求到 USGS FDSN 接口
↓
接收 GeoJSON 格式响应
↓
保存原始 JSON 快照到 source_snapshot/ 目录
↓
解析 JSON，提取地震事件字段
↓
保存原始 CSV 到 data/raw/ 目录
↓
清洗、去重
↓
生成处理后 CSV 到 data/processed/ 目录
```

采集脚本位于 `2_源码/crawler/`，关键实现包括：

- **超时控制**：请求超时设置为 30 秒，避免长时间等待；
- **自动重试**：网络失败时自动重试最多 3 次；
- **HTTP 状态码检查**：只有收到 200 状态码时才解析数据；
- **低频访问**：一次运行只发少量请求，不频繁调用；
- **不绕过访问限制**：遵守网站 robots.txt 和服务条款；
- **离线缓存**：网络失败时使用上一次成功采集的真实数据；
- **无假数据生成**：如果既无网络数据也无缓存，系统明确报错退出。

### 2.3 数据真实性与可追溯性

系统通过以下机制保证数据真实可追溯：

- **保存原始响应**：每次采集都保存原始 GeoJSON 快照到 `source_snapshot/` 目录；
- **保存元数据**：每次成功采集都生成 `source_metadata.json`，记录采集时间、参数、HTTP 状态码、记录数和 SHA256 校验值；
- **保存采集日志**：`crawl_log.txt` 记录每次采集的详细过程；
- **保存来源链接**：每条记录包含 `detail_url` 字段，链接到 USGS 官方事件详情页面；
- **文件校验**：原始文件 SHA256 值保存在元数据中，可用于验证文件完整性。

### 2.4 数据字段说明

| 字段名 | 中文含义 | 说明 |
|--------|----------|------|
| event_id | 地震事件编号 | USGS 事件唯一标识符 |
| event_time_utc | 发震时间（UTC） | 协调世界时 |
| event_time_beijing | 发震时间（北京时间） | UTC+8 时区 |
| latitude | 纬度 | 震中纬度 |
| longitude | 经度 | 震中经度 |
| depth_km | 震源深度 | 单位为公里 |
| magnitude | 震级 | 地震震级，如 4.4、5.2 |
| magnitude_type | 震级类型 | 如 mb（体波震级）、ml（近震震级）、mww（矩震级） |
| place | 参考位置 | USGS 提供的位置描述，如"77 km E of Wāngjing, India" |
| source | 数据来源 | 固定为"USGS" |
| detail_url | 原始详情链接 | USGS 事件详情页面 URL |

### 2.5 数据清洗过程

实际的数据清洗步骤（由 `data_cleaner.py` 实现）包括：

1. **时间格式统一**：将事件时间转换为标准日期时间格式；
2. **UTC 转北京时间**：在采集阶段即转换出北京时间字段；
3. **数值类型转换**：将经纬度、深度、震级转换为浮点数；
4. **缺失值处理**：删除震级、经纬度缺失的记录；
5. **无效值过滤**：删除负震级的无效记录；
6. **去重**：按 `(时间, 纬度, 经度, 震级)` 四维键删除重复事件；
7. **字段标准化**：字符串字段去除首尾空格。

清洗后的数据保存为 `earthquake_events_processed.csv`，作为系统运行的最终数据源。清洗过程不对真实震级、深度、坐标进行随机填充或篡改。

### 2.6 真实地震数据与测试场景的区别

本系统中的真实地震数据包含：事件时间、震级、深度、经纬度、参考位置和来源链接。这些数据来自 USGS 官方公开目录，是已经发生的地震事件记录。

系统测试输入包括：人员身份、年龄、用户位置和行动能力。这些用于验证个性化文本生成功能，属于系统测试和交互信息，不代表实际受灾人员数据。

## 3 系统总体设计

### 3.1 系统技术路线

```
USGS 官方地震目录（FDSN Web Service）
↓
真实地震数据网络采集（crawler 模块）
↓
原始数据保存与来源记录（raw 目录 + 元数据）
↓
数据清洗与去重（data_cleaner.py）
↓
用户选择真实地震事件
↓
输入人员身份、年龄、位置、行动能力
↓
构建用户画像（user_profile.py）
↓
自动判断重点需求（warning_rules.py）
↓
生成个性化地震应急提醒（warning_generator.py）
↓
手机弹窗展示 + Dashboard 数据统计
```

### 3.2 系统架构

系统分为以下几层：

1. **数据采集层**（`crawler/`）：负责从 USGS 官方接口采集真实地震数据；
2. **数据处理层**（`data_loader.py`、`data_cleaner.py`）：负责读取、清洗和保存数据；
3. **规则与文本生成层**（`user_profile.py`、`warning_rules.py`、`warning_generator.py`）：负责用户画像判断、风险等级计算和文本生成；
4. **Flask 服务层**（`app.py`）：处理 HTTP 路由和请求；
5. **前端交互与展示层**（`templates/`、`static/`）：提供 Web 页面和手机弹窗交互；
6. **环境检测与运行辅助层**（批处理脚本、环境检测脚本）：方便部署和运行。

### 3.3 功能模块说明

| 模块 | 主要文件 | 功能 |

## 4 项目使用的关键技术

### 4.1 Python

Python 是项目的主要开发语言。在项目中，Python 用于以下任务：

- **网络数据采集**：使用 requests 库访问 USGS 接口；
- **数据清洗**：使用 pandas 进行格式转换和去重；
- **用户画像判断**：根据条件分支判断用户人群；
- **文本生成**：拼接事件信息和用户画像生成提醒文本；
- **图表绘制**：使用 matplotlib 绘制统计图；
- **Flask 后端**：构建 Web 服务。

选择 Python 的原因是它生态丰富、语法简洁，适合快速开发原型系统。

### 4.2 Flask

Flask 是一个轻量级 Python Web 框架。在项目中，Flask 负责：

- 显示首页，加载真实地震事件列表；
- 接收用户输入（人员身份、年龄、位置等）；
- 调用后端生成逻辑；
- 返回个性化地震应急提醒；
- 提供 Dashboard 数据统计页面。

Flask 简单灵活，适合本项目的课堂演示场景。

### 4.3 requests

requests 是 Python 中最常用的 HTTP 请求库。项目使用它访问 USGS 的 FDSN 接口，发送 GET 请求获取 GeoJSON 格式的地震目录数据。采集时设置了超时时间和重试机制，确保网络异常时程序不会卡死。

### 4.4 Pandas

Pandas 是 Python 的数据分析库。在项目中，Pandas 用于：

- 读取原始 CSV 格式的地震数据；
- 清洗字段（时间格式统一、数值类型转换）；
- 删除重复记录；
- 生成处理后数据；
- 为统计图表提供数据。

### 4.5 Matplotlib

Matplotlib 是 Python 的绘图库。项目使用它生成四张统计图：

- **震级分布图**：展示不同震级区间的事件数量；
- **震源深度分布图**：展示不同深度区间的事件数量；
- **地震事件时间趋势图**：展示每日事件数变化；
- **地震经纬度散点图**：展示事件的空间分布。

### 4.6 GeoJSON 数据解析

USGS 接口返回的是 GeoJSON 格式的结构化数据，包含 `features` 数组，每条 feature 包含 `properties`（事件属性）和 `geometry`（坐标信息）。程序从中提取时间、震级、深度、经纬度和位置描述等字段。

### 4.7 用户画像

用户画像不是识别用户的真实身份，而是根据用户输入的信息生成适合当前提醒的人群标签。具体规则如下：

- 年龄小于 18 岁：标记为"学生/未成年人群体"；
- 年龄大于等于 60 岁：标记为"老年重点关注人群"；
- 身份为游客：标记为"外来不熟悉环境人群"；
- 身份为应急人员：标记为"应急处置工作人员"；
- 行动能力较弱或需协助：标记为"优先协助转移人群"。

以上标签可以组合，例如一个 72 岁的"需协助"居民会被标记为"老年重点关注人群、优先协助转移人群"。

对应代码模块：`code/user_profile.py`。

### 4.8 规则模板文本生成

系统生成个性化提醒不是简单的文字拼接，而是按照以下结构化流程：

1. 获取选中的真实地震事件信息；
2. 根据用户身份、年龄和行动能力判断用户画像；
3. 根据真实震级计算课程演示风险等级；
4. 根据用户画像自动匹配重点需求；
5. 根据用户身份和行动能力选择对应的行动建议；
6. 组合成完整的提醒文本。

所有规则都在 `code/warning_rules.py` 中明确定义，每条生成结果都能追溯到具体规则。

### 4.9 浏览器定位

页面提供"一键定位"按钮，使用浏览器自带的 Geolocation API 获取用户当前位置的经纬度，自动填入位置输入框。当前定位功能仅获取经纬度坐标，未接入地图逆地理编码服务，因此用户也可以手动输入位置文字。

### 4.10 HTML、CSS 和 JavaScript

- **HTML**：构建页面结构，包括表单、地震事件选择、手机弹窗区域等；
- **CSS**：定义页面样式，包括手机设备外观、弹窗动画、玻璃拟态效果等；
- **JavaScript**：处理页面交互，包括事件选择、表单提交、定位请求、弹窗显示等。

### 4.11 离线缓存

系统在网络采集失败时不会生成模拟地震数据，而是自动使用上一次成功采集并缓存的真实数据。如果缓存也不存在，系统会明确报错退出。相关实现在 `update_earthquake_data.py` 中。

### 4.12 一键环境检测与启动

项目提供了以下批处理脚本，方便在不同电脑上快速部署和运行：

- `一键环境检测.py`：检查 Python 版本、依赖安装、项目文件完整性；
- `一键更新真实地震数据.bat`：采集最新真实地震数据并生成统计图；
- `一键启动演示.bat`：环境检测 + 数据更新 + 服务启动 + 浏览器打开；
- `一键安装依赖.bat`：安装 requirements.txt 中列出的依赖。

## 6 核心算法与规则设计

### 6.1 地震演示等级计算

系统根据真实地震事件的震级自动计算课程演示风险等级，规则如下：

| 震级范围 | 演示等级 | 含义 |
|----------|----------|------|
| M < 3.0 | 蓝色 | 普通提醒 |
| 3.0 ≤ M < 4.5 | 黄色 | 注意防范 |
| 4.5 ≤ M < 6.0 | 橙色 | 准备避险 |
| M ≥ 6.0 | 红色 | 立即避险或转移 |

如果用户通过浏览器定位提供了经纬度坐标，系统还会使用 Haversine 公式计算用户与震中的距离，对关注程度做演示性调整。

**重要说明**：该等级仅用于课程系统的文本展示，不等同于官方地震预警等级、地震烈度或应急响应等级。

### 6.2 用户画像构建

用户画像判断逻辑如下：

```
年龄 < 18 → 学生/未成年人群体
年龄 ≥ 60 → 老年重点关注人群
身份 = 游客 → 外来不熟悉环境人群
身份 = 应急人员 → 应急处置工作人员
行动能力 = 较弱/需协助 → 优先协助转移人群
```

多个标签可以叠加。例如：65 岁的游客且行动需协助 → "老年重点关注人群、外来不熟悉环境人群、优先协助转移人群"。

### 6.3 重点需求判断

系统根据用户画像自动判断重点需求：

| 条件 | 重点需求 |
|------|----------|
| 应急人员 | 应急响应与巡查排险 |
| 年龄 ≥ 60，行动需协助 | 转移协助与居家避险 |
| 年龄 ≥ 60，行动正常 | 居家避险与社区关注 |
| 年龄 < 18 | 校园避险与有序撤离 |
| 游客 | 景区疏散与安全指引 |
| 其他 | 居家避险与风险关注 |

### 6.4 个性化文本生成

生成的提醒文本包含以下结构：

```
【地震提醒】公开地震目录显示，{发震时间} 在 {位置} 发生 {震级} 地震，震源深度 {深度}。
您属于{用户画像}。{距离信息}
系统识别的重点需求：{重点需求}。
行动建议：{行动建议}
数据来源：{来源}。
{课程演示等级说明}
{课程免责声明}
```

### 6.5 差异化应急建议

系统针对不同人群生成了差异化的行动建议：

- **普通居民（成年人）**：保持冷静，就近躲避，远离玻璃和悬挂物，震动停止后撤离；检查家中燃气和水电设施。
- **未成年人（学生）**：听从学校、老师或监护人安排，不拥挤奔跑，保护头部，有序撤离到安全区域。
- **老年人**：不要独自快速撤离，及时联系家属或社区，优先获得协助，避免摔倒和拥挤。
- **游客**：关注当地官方信息，远离山体、危墙和老旧建筑，服从景区疏散安排。
- **应急人员**：立即到岗到位，开展震后巡查排查，检查建筑物受损和次生风险，协助重点人群转移。
- **行动不便人员**：提前联系救援人员协助，不要单独行动。

## 7 系统实现过程

### 7.1 数据采集实现

数据采集模块位于 `crawler/` 目录：

- `fetch_usgs.py`：向 USGS FDSN 接口发送 GET 请求，接收 GeoJSON 数据，提取事件字段，保存原始快照；
- `fetch_ceic.py`：尝试采集中国地震台网数据（当前因反爬机制无法稳定获取）；
- `update_earthquake_data.py`：统一入口，按顺序尝试 CEIC 和 USGS，去重后保存，记录日志和元数据。

采集后的数据同步到 `1_数据包/` 目录，便于归档和提交。

### 7.2 数据处理实现

`main.py` 是数据处理脚本，分为四个步骤：

1. 读取真实地震事件数据（调用 `data_loader.py`）；
2. 清洗数据（调用 `data_cleaner.py`）；
3. 保存处理后的数据；
4. 生成四张地震统计图表（调用 `visualization.py`）。

### 7.3 Flask 后端实现

`app.py` 是 Flask Web 应用，主要路由包括：

- `GET /`：首页，加载真实地震事件列表；
- `GET /get_event_detail`：根据 event_id 返回地震事件详情；
- `POST /generate`：接收用户输入，调用生成逻辑，返回个性化提醒；
- `GET /dashboard`：数据统计页面。

### 7.4 首页交互实现

首页（`templates/index.html`）左侧为表单，包含：

- **人员身份下拉框**：普通居民、游客、应急人员；
- **年龄输入框**：系统根据年龄自动识别学生或老年人；
- **位置输入**：支持手动输入或一键定位；
- **地震事件下拉框**：显示最近 50 条真实事件，选择后自动展示事件详情卡片；
- **监测灾种显示**：固定为"地震"；
- **行动能力下拉框**：正常、较弱、需协助。

### 7.5 手机预警弹窗实现

页面右侧模拟手机设备，包含：

- **正常状态**：显示手机锁屏图片；
- **生成后状态**：手机图切换为高斯模糊背景，弹出预警通知卡片；
- **弹窗内容**：地震事件信息、用户画像、重点需求、演示风险等级、行动建议、完整文本和免责声明。

### 7.6 Dashboard 实现

Dashboard 页面（`/dashboard`）展示：

- **统计概览**：真实地震记录数、数据来源、最大震级、平均深度、最新数据时间；
- **四张统计图**：震级分布图、深度分布图、时间趋势图、地理散点图；
- **数据表格**：最近 20 条真实地震事件，包含发震时间、震级、深度、经纬度、位置和来源；
- **免责声明**：页面顶部注明数据来源于公开地震目录。


浏览器访问：http://127.0.0.1:5000
