# 第一部分 · 项目导览

## 1.1 这个项目是做什么的

**一句话**：用 BERT+CRF 深度学习模型从灾害求救文本（"急！郑州京广路隧道被淹，水深 2 米，有人被困，急需救援，联系 138xxxx"）里自动抽出**地点/人员/灾情/需求**四类实体，再把地点翻译成经纬度，最后生成一张**求救点分布交互地图**（rescue_map.html）。

灾害时社交平台求救信息几分钟几百条，人工分拣根本来不及。本项目端到端演示"**文本 → 结构化表格 → 地图定位**"：模型测试集实体 F1 达 **0.95**（规则基线只有 0.31），288 条文本全部完成结构化与定位。

## 1.2 先看成品（不用动手，双击打开就行）

| 位置 | 看什么 |
|---|---|
| `源码\outputs\maps\rescue_map.html` | **双击用浏览器打开**——288 个求救点分布地图，红/橙/黄=紧急程度，可搜索、可点击飞行定位 |
| `源码\outputs\reports\training_curve.png` | 训练曲线（F1 如何一步步涨到 0.97） |
| `源码\outputs\reports\metrics.json` | 成绩单：BERT F1 0.9511 vs 规则基线 |
| `数据集\processed\structured_results.csv` | 288 条文本的抽取结果表（Excel 打开） |

## 1.3 输入与输出

**吃进去（输入）**：
- `数据集\raw\distress_messages_raw.jsonl`：288 条求救文本（带实体标注）——由 68 条人工种子 + 220 条模板程序生成（种子 42，可完全复现）；
- `数据集\geo\china_geo_dict.json`：212 条中国地名→经纬度字典（本地地理编码库）；
- BERT 预训练模型（约 400MB，**首次需联网下载**，见 2.5）。

**吐出来（输出）**：
- `outputs\checkpoints\bert_ner_best\`：训练好的模型；
- `outputs\reports\`：metrics.json / training_curve.png / badcase.txt（错误案例分析）等；
- `数据集\processed\structured_results.csv`：288 行抽取+定位结果（列：原文/地点/人员/灾情/需求/紧急度/经纬度）；
- `outputs\maps\rescue_map.html`：交互地图（纯本地，双击即看）。

## 1.4 业务流程图

```
288 条求救文本（种子+模板生成，7:1:2 划分 201/28/59）
        │  清洗：去URL/@/#话题#，繁转简
        ▼
字符级 BIO 标注（每个字打一个标签：B-LOC I-LOC / O / B-NEED...）
        ▼
BERT+CRF 模型训练（BERT 提特征，CRF 保证标签序列合法）
        │
        ▼
评估：实体级严格匹配 F1（类型+边界全对才算对）
        │
        ▼
批量推理 288 条 → 抽出四类实体
        ▼
地理编码：本地 212 地名库最长匹配 → 高德/百度 API 兜底
        ▼
紧急度分级（救命/SOS→红，紧急/求救→橙）→ rescue_map.html
```

## 1.5 用到哪些技术（人话版）

| 技术名词 | 人话解释 |
|---|---|
| NER（命名实体识别） | 从文本里找出"有特定类型的词"（这里是地点/人员/灾情/需求） |
| BERT | 谷歌的预训练语言模型：读完海量文本后，每个字都带"语义理解" |
| 微调（fine-tune） | 在预训练模型上加一个小输出层，用自己的数据继续训练 |
| CRF（条件随机场） | 给标签序列加"转移规则"：I-LOC 不能跟在 B-PER 后面这种约束 |
| BIO 标注 | 每个字打标签：B=实体开始，I=实体内部，O=无关 |
| seqeval 严格评估 | 实体的类型和边界全对才算对——NER 界的严格评分器 |
| Isolation/最长匹配 | 地名库里"四川汶川映秀镇"优先匹配最长的地名 |
| 地理编码 | 文本地名 → 经纬度坐标 |
| Leaflet/MarkerCluster | 开源网页地图库 / 海量点位聚合显示 |

## 1.6 做完这个项目，你将学会什么

- 理解 **NLP 序列标注**任务的完整链路：数据→标注→模型→评估→推理→应用；
- 明白 BERT 为什么强（预训练的语义先验）、CRF 加在哪、有什么用；
- 会做实体级严格评估，理解为什么不能按"字准确率"报 NER 成绩；
- 理解"小数据冷启动"手法：模板合成 + 自动标注对齐；
- 学会本地优先、在线兜底的地理编码架构。

# 第三部分 · 理解手册

## 3.1 背景：灾难中的"信息洪流"

2021 年河南暴雨中，一份《待救援人员信息》在线表格在几小时内涌入数十万条求助与救援信息，志愿者手工整理到凌晨——**信息的速度超过了人力**。把"自然语言的求救"变成"表格里的结构化记录 + 地图上的一个点"，是指挥调度自动化的第一步。本项目就是这个"第一步"的完整教学实现。

## 3.2 核心概念逐个讲

### 3.2.1 序列标注与 BIO

NER 的主流做法是给**每个字**打标签。"郑州"两个字标 B-LOC、I-LOC，"被淹"标 O、O。9 种标签（O + B/I × 4 类）。模型本质是"逐字分类器"，但要保证拼出来的实体合法。

### 3.2.2 BERT：为什么先读"闲书"再读"课本"

bert-base-chinese 预训练时读了几十亿字中文，已经懂"京广路是个路名"这类常识。我们只需在它头上加一个线性层（768 维→9 标签），用 201 条样本微调——**小数据也能训出好模型，靠的就是预训练的先验**。这就像学生先读了十年闲书再来学专业课，一点就通。

### 3.2.3 CRF：标签之间的"语法警察"

纯分类器可能输出 B-LOC 后面跟 I-PER 这种非法序列。CRF 层学习一个**标签转移矩阵**（B-LOC→I-LOC 分数高，B-LOC→I-PER 分数极低），解码用 Viterbi 找全局最优标签链。`src/models/crf.py` 手写了前向算法和 Viterbi——不用调库，每一行公式都能对照课件看懂。

### 3.2.4 严格实体级评估（seqeval）

"字准确率 99%" 在 NER 里毫无意义——288 条文本里 95% 的字都是 O，全猜 O 就有 99%。严格评估要求**实体类型+起止位置完全一致**才算对。对照两个数字（规则基线 F1 0.31 vs BERT+CRF 0.95）就能体会模型差距。

### 3.2.5 模板合成数据与自动标注（build_dataset.py / annotate.py）

68 条人工种子 + 220 条模板渲染（地名×灾情×人员×需求×话术），生成时同步记录实体位置——**标注 100% 准确且免费**。这是小数据冷启动的经典手法，也是本项目的"数据工厂"。

### 3.2.6 地理编码：本地优先、在线兜底

212 个地名按**长度降序**做最长匹配（"四川汶川映秀镇"优先于"汶川"），命中率 100% 时完全离线；未命中的走高德→百度 API（含 BD09→GCJ02 坐标系转换——不同地图厂商坐标加密不同的坑）。**可用性设计：离线也能跑通主线。**

### 3.2.7 纯离线的交互地图（visualize.py）

不用 Python 的 folium，而是手写 526 行 HTML：Leaflet/jQuery/MarkerCluster 全部本地引用（零 CDN），数据内嵌 JSON——**断网双击就能用**，适合灾区演示场景。

## 3.3 代码精讲

| 模块 | 读什么 |
|---|---|
| `src/config.py` | 全局配置：路径/标签表/超参（先读它） |

## 3.4 动手改一改

**练习 1（入门）· 加几条自己的求救文本**
- 改哪：跑 `python -m src.infer --text "急！XX市XX路发生山体滑坡，3人被困，急需挖掘机"`（不训练直接用现成模型）。
- 预期：抽出地点/灾情/需求。
- 学到：模型的单条推理接口。

**练习 2（入门）· 砍掉 CRF 看 F1 掉多少**
- 改哪：训练加参数 `--no_crf`，重新训练后评估。
- 预期：F1 略降、非法标签序列增多。
- 学到：消融实验验证 CRF 的贡献。

**练习 3（进阶）· 减少训练数据**
- 改哪：`src/data/annotate.py` 的划分比例 0.7→0.3（训练集变小），重建数据+训练。
- 预期：F1 下降——感受"数据量曲线"。
- 学到：小样本对微调的影响。

**练习 4（挑战）· 加一类实体**
- 改哪：config.py 的 TAG_LIST 加 B/I-PHONE（电话号码），build_dataset 模板加电话、annotate 对应标注，重新全流程。
- 预期：模型学会抽电话号码。
- 学到：扩展 NER 类型的完整改动链——配置→数据→标注→模型输出维度。

## 3.5 怎么读结果

- **metrics.json**：bert 的 per_type 里 LOC/PER/DIS/NEED 各自的 P/R/F1——哪类最难？（通常 NEED 最难：'食物''水''帐篷'太多样）
- **badcase.txt**：前 20 条错误样本，逐条看是"边界错"还是"类型错"——错误分析是 NLP 工程师的核心日常；
- **rescue_map.html**：红色点（emergency）分布是否聚集？——聚集区就是救援优先级；
- **training_curve.png**：dev F1 的爬升曲线，看第几轮开始过拟合（train 还在涨 dev 不涨）。

## 3.6 思考题

1. 合成数据训出的模型，放到真实微博文本上表现会怎样？差在哪（口语化/错别字/新地名）？
2. 为什么按 dev F1 而不是 train loss 保存最佳模型？
3. 本地地名库只有 212 条，真实中国地名百万级。怎么扩？（提示：行政区划库/在线 API 策略）
4. 紧急度用关键词规则判断。如果用模型预测，需要什么数据？
