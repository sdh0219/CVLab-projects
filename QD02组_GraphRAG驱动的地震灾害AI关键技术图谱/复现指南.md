# 第一部分 · 项目导览

## 1.1 这个项目是做什么的

**一句话**：把 49 篇地震防灾文献（论文/专利/政策/案例/标准等 7 类各 7 篇）用自研的 GraphRAG 流水线抽取成"实体-关系-证据"知识图谱（如 `地震应急辅助决策 --USES_MODEL--> 大语言模型 --VALIDATED_IN--> 海地地震救援`），再发布成一个**可交互的网页图谱**，支持三种检索问答。

它解决的是"文献太多读不过来"的问题：想知道"哪些 AI 技术用在地震预警上？哪些只有论文没有实际案例验证？"——人工翻文献要几天，图谱检索几秒钟。**GraphRAG = 知识图谱 + 检索增强生成**，是 2024 年以来 RAG 领域最热的方向（微软 GraphRAG 论文的复现与改造）。

## 1.2 先看成品（不用动手，双击/浏览器打开就行）

主工程里已经内置了构建好的图谱和前端快照（10 篇文档版：199 个实体、270 条关系、8 个技术社区）：

1. 用 VS Code（或任意编辑器）打开 `源码\2_源码\GraphRAG驱动的地震灾害AI关键技术图谱_前端页面\public\atlas\atlas_frontend.json`——这就是图谱数据本体；
2. `outputs\graphrag_index\exports\` 里的 CSV 可以用 Excel 看：`graph_nodes.csv`（实体清单）、`evidence_edges.csv`（关系与证据）；
3. 跑通前端后（2.6）能看到力导向交互图谱：点节点展开、按社区着色。

## 1.3 输入与输出

**吃进去（输入）**：
- `data\corpus\sample\`：49 篇带 frontmatter 的 Markdown 文献整理稿（每篇注明来源类型/年份/地区/灾种）；
- `config\ontology.json`：本体定义——16 种实体类型、15 种关系类型、每个实体的别名表。

**吐出来（输出）**：
- `outputs\graphrag_index\`：documents/chunks/entities/claims/relations/community_reports 六类 JSONL + 汇总；
- `exports\`：技术节点/场景节点/证据边 CSV、GraphML（Gephi 可开）、**Neo4j 导入脚本**、关键技术成熟度评估、质量报告；
- `public\atlas\atlas_frontend.json`：前端快照；
- 运行 `npm run dev` 后的交互网页（http://localhost:3000）。

## 1.4 业务流程图

```
49 篇文献（Markdown + frontmatter 元数据）
        │  按空行切段、每段 ≤520 字切块（chunk）
        ▼
实体关系抽取（三种模式任选）：
   rule  纯规则：本体别名表字符串匹配（离线、快、确定）

        ▼

        ▼
多格式导出：JSONL / CSV / GraphML / Neo4j 脚本 / 前端快照
        ▼
三种检索 + 交互网页图谱
   global：问"有哪些技术社区"（社区报告检索）
   local：  问"某技术的关系网络"
   gap：   问"哪些技术缺案例验证/缺数据依赖"（查漏）
```

# 第三部分 · 理解手册

## 3.1 背景：从"读文献"到"查图谱"

防灾领域一年的新文献远超任何人的阅读能力。传统 RAG（切块+向量检索）回答"某句话在哪篇文献"很行，但回答**关系型问题**（"A 技术在哪些灾害里验证过？"）很弱——因为答案分散在几十篇文档里，需要**结构化关联**。GraphRAG 的主张：先花一次性成本把语料抽成图谱，之后的关系问答都是结构化查询。

## 3.2 核心概念逐个讲

### 3.2.1 本体（Ontology）：图谱的宪法

`config/ontology.json` 预先规定了 16 种实体类型（AITech/Dataset/Model/DisasterEvent/Scenario…）和 15 种关系（USES_MODEL/DEPENDS_ON/VALIDATED_IN/LIMITED_BY…），每种实体还带别名表（如"大语言模型/LLM/大模型"都是同一实体）。**先定_schema_再抽取**——这是知识工程的第一原则，和"先建表再插数据"同理。

### 3.2.2 规则抽取：确定性的笨办法（extractor.py）

对每个块，把本体里所有实体名/别名做大小写不敏感的子串匹配；两个实体共现且类型组合符合某条关系规则就连边。置信度公式 `min(0.95, 0.55+0.08×实体数)`。**优点**：离线、免费、100% 可复现；**缺点**：换个说法就认不出（"大语言模型"≠"LLM"除非别名表里写了）。

### 3.2.3 LLM 抽取与本体校验防幻觉（llm_extractor.py）

把本体实体表塞进 prompt 让大模型抽取。关键在**解析后校验**（`_parse_response`）：实体必须在候选表里、(源类型,关系,目标类型) 三元组必须在本体规则里，**非法一律丢弃**——模型只能"选"，不能"造"。这是对 LLM 幻觉最朴素的工程防御。

### 3.2.4 Hybrid 与缓存工程

rule 和 llm 结果按 stable_id（内容 sha1 前 16 位）合并去重。LLM 请求带 sha256 响应缓存 + 429 指数退避重试——**调 API 的两个省钱省命细节**，值得抄进任何项目。

### 3.2.5 三种检索对应三种问题

- **global**（社区级）：词面重叠给社区报告打分——回答"宏观有哪些"；
- **local**（实体级）：取实体邻域前 20 关系+声明——回答"某个东西的脉络"；
- **gap**（查漏）：检查每个 AITech 是否缺 VALIDATED_IN/DEPENDS_ON/LIMITED_BY——回答"哪里证据不足"。**gap 检索是本项目的独门价值**：文献综述不再只总结已知，还能指出空白。

### 3.2.6 多格式导出

同一张图谱导出 JSONL（程序用）、CSV（Excel 用）、GraphML（Gephi 可视化）、`neo4j_import.cypher`（图数据库导入脚本，含动态边类型）——**数据与工具解耦**，别人想用 Neo4j 就导 Neo4j。
