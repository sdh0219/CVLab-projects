# 地震灾害AI关键技术图谱项目实现与运行说明

## 1. 项目目标

本项目是一个可运行的 GraphRAG 风格工程原型，当前研究尺度统一为地震灾害：

```text
地震论文 / 地震相关专利 / 地震示范项目 / 地震政策预案 / 地震案例 / 地震适用标准 / 地震相关报告
  -> GraphRAG 抽取实体、关系、声明、证据来源
  -> 构建地震关键技术社区和 community reports
  -> 面向问题检索与归纳
  -> 发现地震早期预警、震后损毁评估、应急调度、生命线风险和证据链问答等技术簇
  -> 专家校验
  -> 沉淀为地震灾害AI关键技术图谱
```

## 2. 项目结构

```text

  publish_atlas_frontend.py      # 前端快照生成
  validate_atlas_outputs.py      # 输出结构校验
  build_final_deliverables.py    # 最终报告与提交包生成
graphrag_atlas/
  __main__.py                    # CLI入口
  models.py                      # 数据结构
  io_utils.py                    # 文档读取、切块、JSONL输出
  extractor.py                   # 本地规则抽取器
  llm_extractor.py               # OpenAI-compatible LLM抽取器与hybrid抽取器

  pipeline.py                    # 索引管线与CSV导出

```

## 3. 快速运行

推荐使用 `npm.cmd`，避免 Windows PowerShell 执行策略拦截 `npm.ps1`。

生成地震专题语料：

```bash
npm.cmd run atlas:corpus:earthquake
```

构建规则索引：

```bash
npm.cmd run atlas:index
```

刷新完整图谱成果：

```bash
npm.cmd run atlas:refresh
```

完整执行索引、增强分析、前端发布、结构校验、lint、build 和打包：

```bash
npm.cmd run atlas:all
```

## 4. 查询命令

### 4.1 Global Search

```bash
python -m graphrag_atlas global-search "地震灾害AI防灾减灾有哪些关键技术社区" --output outputs/graphrag_index
```

### 4.2 Local Search

```bash
python -m graphrag_atlas local-search "遥感震损智能解译" --output outputs/graphrag_index
python -m graphrag_atlas local-search tech_remote_sensing_eq_damage --output outputs/graphrag_index
```

### 4.3 Gap Search

```bash
python -m graphrag_atlas gap-search --output outputs/graphrag_index
```

`gap-search` 当前检查每个地震 AI 技术是否缺少：

- 案例验证关系 `VALIDATED_IN`
- 数据依赖关系 `DEPENDS_ON`
- 技术限制关系 `LIMITED_BY`

## 5. 语料格式

每篇文档使用 Markdown + frontmatter：

```text
---
doc_id: paper_bddnet_damage
title: BDD-Net building damage detection from satellite imagery
source_type: paper
source_name: Remote Sensing
source_url: https://www.mdpi.com/2072-4292/12/10/1670
year: 2020
region: global
disaster_type: 地震
---
正文...
```

正文是面向 GraphRAG 抽取的中文整理稿，不是原文全文转载；正式引用时应回到 `source_url` 核验原始来源。

## 6. 本体约束

当前 `config/ontology.json` 包括：

- `DisasterType`：地震
- `Scenario`：震前监测感知、地震风险评估、地震早期预警、震后应急调度、震后损毁评估
- `AITech`：地震早期预警、震后建筑损毁识别、遥感震损智能解译、地震应急辅助决策等
- `Model`：Transformer、U-Net、GNN、LLM、强化学习、CNN、LSTM、机器学习
- `Dataset`：地震台网数据、遥感影像、物联传感器、众源文本、建筑物足迹数据、生命线设施数据
- `Task`：地震监测预警、建筑损毁评估、震后资源调度、证据链问答等
- `Case`：土耳其叙利亚地震、日本能登半岛地震、尼泊尔地震、海地地震等
- `Policy`：地震应急预案、地震预警发布规范、应急管理技术标准等
- `Limitation`：标注稀缺、跨区域泛化不足、实时部署困难、幻觉风险等

关系规则包括：

```text
APPLIES_TO
SERVES_STAGE
SOLVES
DEPENDS_ON
USES_MODEL
VALIDATED_IN
LIMITED_BY
REQUIRED_BY
```

## 8. LLM抽取

三种抽取模式：

| 模式 | 命令 | 行为 |
|---|---|---|
| `rule` | `npm.cmd run atlas:index` | 本地确定性规则抽取，不需要 API key |
| `llm` | `npm.cmd run atlas:index:llm` | 严格 LLM 抽取，缺少 `ATLAS_LLM_API_KEY` 会报错 |
| `hybrid` | `npm.cmd run atlas:index:hybrid` | 规则抽取 + LLM 抽取，LLM 不可用时保留规则结果 |

LLM 抽取器会把输出实体限制在 `config/ontology.json` 的 `entity_id` 内，并过滤非法关系类型和类型不匹配的边。

## 9. 当前边界

当前项目已经是可运行工程，但仍是第一版本地原型：

- 专家审核表为 `pending` 初始状态，不代表已完成人工专家评审；
- 社区报告仍以规则化证据聚合为主；
- Neo4j 导入文件已生成，但仍需在真实图数据库中执行；
- LLM 抽取需要用户自行配置 API key；
- 后续可把社区发现替换为正式 Leiden 或 Microsoft GraphRAG 社区发现流程。


其中 `atlas_frontend.json` 为主快照，包含摘要指标、语料层、社区报告、导出清单和 `graphData` 完整节点边数据；`graph_visualization.json` 作为交互图谱的兼容备用快照。

新增交互能力：

- 点击节点：设置为当前节点并展开一跳邻居；
- 连续点击邻居：继续逐层展开相关节点；
- 展开一跳、展开两跳：按证据片段、置信度和实体类型优先级扩展；
- 收起到当前节点：保留当前节点及其核心邻域；
- 重置视图：恢复初始核心地震技术节点；
- 显示全部节点：展示当前快照中的全部图谱节点；
- 只看证据链：只保留带证据或文档来源的关系边；
- 搜索节点：按名称、id 或实体类型定位并展开节点；
- 关系类型筛选：筛选 `APPLIES_TO`、`SERVES_STAGE`、`SOLVES`、`DEPENDS_ON`、`USES_MODEL`、`VALIDATED_IN`、`LIMITED_BY`、`REQUIRED_BY` 等关系；
- 实体类型筛选：筛选 `AITech`、`Scenario`、`Model`、`Dataset`、`Task`、`Case`、`Policy`、`Limitation`、`DisasterType` 等实体；
- 点击边：查看关系类型、起点、终点、置信度、证据片段、doc_id、chunk_id、source_name 和 review_status。

验证命令：

