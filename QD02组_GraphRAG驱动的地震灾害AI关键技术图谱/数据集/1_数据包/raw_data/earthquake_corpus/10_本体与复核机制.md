# 本体与复核机制

## 十、 基于GraphRAG的知识图谱领域本体与评测复核系统设计

在实现地震灾害 AI 关键技术图谱时，必须从顶层构建高表现力的知识图谱本体（Ontology） [1]。

参照项目资料收集目录总表 [1] 的技术演进逻辑，图谱应统一定义 10 类核心概念节点（Nodes）和 6 类主要关联边（Edges） [1]。

─── SOLVES ───► ─── SOLVED_IN ───► │ ▲ │ (USES_MODEL) │ (SOLVES) ▼ │ [ Model ] ─────────────────────+ ─── VALIDATED_IN ───► [ Case ] │ │ (DEPENDS_ON) ▼ ◄── REQUIRED_BY ─── [ Policy ] ▲ │ (LIMITED_BY) ▼ [ Limitation ]


表 9

| 实体/关系英文标识 | 实体/关系中文标识 | 图谱本体语义定义与物理节点对应属性规范 | 边关系约束与推理规则 (Source -> Target Constraint) |
| --- | --- | --- | --- |
| AITech | AI关键技术 | 泛指防灾减灾中的核心前沿AI技术大类（如 基于图神经网络的结构易损性分析技术） [1] | 不直接关联具体代码库，作为高级分类中介 [1] |
| Model | 计算模型 | 具体的计算、感知、解译或预测算法（如 PhaseNet, EQTransformer, LEGG） [50, 72, 74] | Model -> USES_MODEL -> Model（支持子模型依赖） [1] |
| Dataset | 支撑数据集 | 用于模型训练、测试或校验的底层结构化/非结构化数据集（如 xBD, NGA-West2） [25, 54] | 必须具备明确的许可证属性和版本控制记录 [1] |
| Task | 防灾减灾任务 | AI算法所针对并期望解决的物理工程任务（如 震后倒塌建筑物智能快速识别） [1] | Model -> SOLVES -> Task [1] |
| Scenario | 应用场景 | 任务执行所对应的时空及边界场景限制（如 云层遮挡下的夜间震损高难度遥感反演） [1] | 关联具体的行业标准和合规安全边界 [1] |
| Case | 典型历史案例 | 真实发生的地震灾害事件（如 2024年能登半岛地震, 2023年土耳其强震） [2, 9] | Model/System -> VALIDATED_IN -> Case [1] |
| Policy | 应急政策标准 | 发挥法律、行政或技术规约约束力、强制力要求的政策规章或技术规范标准（如 ISO 22320） [91] | Dataset/Model -> REQUIRED_BY -> Policy [1] |
| Limitation | 技术局限性 | 技术在运行、推理及跨区应用时的局限、瓶颈与高风险虚警点（如 小震级虚警高噪声敏感） [100] | Model/AITech -> LIMITED_BY -> Limitation [1] |
| DisasterType | 灾害关联大类 | 地震引起或伴随发生的物理次生/衍生灾害大类（如 斜坡液化, 海啸, 火灾, 崩塌） [2, 35] | 用于灾害物理演进动力链条关联 [1] |
| USES_MODEL | 使用模型关系 | 表示 AI 技术在实际落地方案中采用了何种特定模型的算法内核 [1] | AITech -> USES_MODEL -> Model [1] |
| DEPENDS_ON | 依赖关系 | 表征特定计算算法、模型对于底层训练、标定数据集或特定传感器数据的强物理依赖 [1] | Model -> DEPENDS_ON -> Dataset [1] |
| SOLVES | 求解任务关系 | 建立具体技术或算法与抗震救灾中所需完成的工程性任务之间的语义指向关联 [1] | Model -> SOLVES -> Task [1] |
| VALIDATED_IN | 案例验证关系 | 确定特定防灾 AI 工程系统在某一真实地震灾害事件中经受了实战测试和检验 [1] | System -> VALIDATED_IN -> Case [1] |
| LIMITED_BY | 局限约束关系 | 指向并暴露该 AI 算法目前的物理盲区、泛化能力天花板、数据偏差影响或高耗能瓶颈 [1] | Model -> LIMITED_BY -> Limitation [1] |
| REQUIRED_BY | 政策合规要求 | 关联模型或数据集开发在输出结果、地理精度以及隐私伦理上受何种法规标准约束 [1] | Dataset/Model -> REQUIRED_BY -> Policy [1] |

为了确保基于该图谱的 GraphRAG 证据问答检索结果的无幻觉性，必须在图谱数据层单独构建对应的“GraphRAG 问答评测集”与“专家复核质量控制模板” [1]。通过在知识图谱底层加入双向核验证据链条属性（如 evidence_text 字段），并在抽取、融合的生命周期中引入专家人工确认状态（review_status），能够使 AI 检索器在生成答案的同时，通过在回答文本中嵌入其对应来源节点和边的引用标签（如 ``），从而使防灾AI系统最终具备可解释和可提交的成果可信度 [1]。

| 字段名称 | 评测与复核项数据格式 | GraphRAG 检索评价机制说明 | 专家核验与质控制度约束 |
| --- | --- | --- | --- |
| 测试问题 (QA Question) | 全局宏观问题与微观细粒度物理问题的双重混合（例如 对于2023年土耳其地震，其同震地表形变最大位移是多少？） [1, 15] | 检测 GraphRAG 是否能在海量图谱拓扑路径中成功进行多跳（Multi-Hop）关联抽取，不发生漏检索 [1] | 问答必须有唯一指向的实体子图，严禁 AI 自行泛化推理不相干内容 [1] |
| 标准参考答案 (Standard Answer) | 包含了具体的物理参数、历史统计数据、引用 DOI 的极结构化陈述文本 [1] | 采用 RAGAS 等自动化评测框架与人工专家盲测相结合的形式进行多维度评分 [1] | 精准度、忠实度、完整度三项指标均须超过 的硬性系统分值 [1] |
| 证据文本块 (Evidence Text) | 从原始核验资料（如 us6000m0xl Supplemental Information）中切片抽出的原生原文字段 [1, 4] | 将该文本块对应的 chunk_id 与图谱中的特定关联边（Edge）的 evidence_id 属性进行强一致性物理绑定 [1] | 若原始核验文本发生内容更迭，对应的图谱关系必须进行级联同步删除或自动重构 [1] |
| 专家复核日志 (Expert Review Log) | 包含：复核主键（review_item_id）、复核结论（保留/修改/删除/待确认）、复核专家唯一签名属性等 [1] | 对关系边和实体属性的置信度低于 0.70 的低置信度清单，强制要求执行专家一票否决权制度 [1] | 每一个领域本体实体及其关联关系，必须有至少两位防灾、地震地学和IT领域的高级职称学者双盲核验记录 [1] |
