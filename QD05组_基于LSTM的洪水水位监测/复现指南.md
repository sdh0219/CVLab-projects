# 第一部分 · 项目导览

## 1.1 这个项目是做什么的

**一句话**：用深度学习（LSTM 神经网络）根据过去几天的河流水位记录，预测未来 24 小时的水位，提前发现洪水风险。

想象一下：一条大河边上有一座城市，河边有一个水位站，每小时自动记录一次水位。数据存了 18 年（2008～2026 年，共 16 万多条记录）。如果只看一条弯弯曲曲的曲线，人是很难判断"明天水位会不会猛涨"的。

这个项目做的事情就是：让程序**从 18 年的历史数据里学会"水位的涨落规律"**，然后告诉它"最近 72 小时的水位是这样的"，它就能算出"未来 24 小时大概会涨到多高"，再对照城市的防洪警戒线，给出风险提示。

## 1.2 先看成品（不用动手，双击打开就行）

在你拿到的项目文件里，装着数据的那个文件夹（现在可能叫 `数据集`，2.4 会把它改名为 `data`）中放着上一届运行留下的成品图。先用看图软件打开它们，你会对"这个项目最终长什么样"有直观印象：

| 文件 | 是什么 | 你怎么看 |
|---|---|---|
| `prediction_plot.png` | 预测 vs 真实水位对比曲线 | 黑线是真实水位，蓝线是模型预测的。**两条线贴得越近，说明预测越准** |
| `risk_plot.png` | 最近水位 + 未来 24 小时预测 + 警戒线 | 橙色虚线是"轻度洪水"警戒线。预测曲线如果碰到线，就是有风险 |
| `model_comparison.png` | LSTM 与 BiLSTM 两个模型对比 | 上图是预测曲线对比，下图是误差对比 |

> 小贴士：这组数据来自美国爱荷华州 Cedar Rapids 市的 Cedar River 水文站（站点编号 05464500）。2008 年 6 月这里发生过特大洪水，最高水位达到 **31.12 英尺**（约 9.5 米）——这就是"为什么提前预测水位"这件事很重要。

## 1.3 输入与输出：这个项目"吃什么、吐什么"

**吃进去（输入）**：`data/cedar_rapids_stage_hourly.csv`，一张 16 万行的表格，每行是某一小时的一条记录：

| 字段 | 含义 | 单位 |
|---|---|---|
| `datetime` | 时间戳 | 年月日时分（UTC 时间） |
| `stage_ft` | 水位（Gage height） | 英尺 |
| `discharge_cfs` | 流量 | 立方英尺/秒 |
| `precipitation_mm` | 该小时降雨量 | 毫米 |
| `stage_m` | 水位（换算成米） | 米 |

**吐出来（输出）**：运行结束后，`outputs` 文件夹里会生成一批文件——训练好的模型、预测结果表、评价指标表、三张图。详细的产物清单见 2.7。

## 1.4 业务流程图：整个项目在跑什么

```
水位站每小时记录数据（18 年，16 万条）
        │
        ▼
数据清洗：小时聚合、缺失值插值、和降雨数据对齐
        │
        ▼
把数据切成"样本"：输入 = 过去 72 小时，输出 = 未来 24 小时
        │
        ▼
训练两个模型：LSTM 和 BiLSTM（从历史数据里学规律）
        │
        ▼
用测试集检验学得怎么样（MAE / RMSE / R² 三个指标打分）
        │
        ▼
拿最新的 72 小时数据 → 预测未来 24 小时水位
        │
        ▼
对照警戒线分级：normal / action / minor / moderate / major
        │
        ▼
输出：预测表 + 预测曲线图 + 风险图 + 模型对比图
```

## 1.5 用到哪些技术（每个词先用"人话"认识一下）

| 技术名词 | 人话解释 |
|---|---|
| Python | 一种非常好上手的编程语言，本项目全部用它写 |
| 时间序列 | 按时间顺序记录的一串数据，比如"每小时的水位" |
| 深度学习 / 神经网络 | 让计算机从大量数据里自己总结规律的一类算法 |
| LSTM | 一种特别擅长处理时间序列的神经网络，能"记住"历史信息。全称是长短期记忆网络 |
| BiLSTM | LSTM 的加强版：不仅从前往后看历史，还从后往前看，往往更准一点 |
| TensorFlow / Keras | 谷歌开源的深度学习框架，"搭积木式"地构建神经网络 |
| pandas / numpy | Python 里处理表格和数字的必备工具库 |
| 滑动窗口 | 把长数据切成"过去 72 小时 → 未来 24 小时"这样的小段，每段就是一个训练样本 |
| 归一化 | 把不同量纲的数字（水位 7 英尺、流量 13000 立方英尺/秒）统一缩放到 0~1 之间，让模型更好学 |
| 训练集 / 测试集 | 数据一分为二：80% 用来"教"模型，20% 藏起来"考"模型，防止它死记硬背 |
| 过拟合 | 模型把教材背得太熟，换个新题就不会了。用 Dropout 和早停来防 |
| MAE / RMSE / R² | 三个"打分表"：衡量预测值和真实值差多少 |

> 这些词的详细讲解在第三部分"理解手册"的 3.2 节，那里会一个一个掰开讲。

## 1.6 做完这个项目，你将学会什么

- 会安装 Python、创建虚拟环境、用命令行运行一个 Python 程序（这是以后所有项目的基本功）；
- 明白一个"用数据做预测"的完整流程长什么样：**数据 → 清洗 → 建模 → 训练 → 评估 → 预测**；
- 能说出 LSTM 是什么、它和普通神经网络有什么不同；
- 会读三个评价指标，能判断一个模型"准不准"；
- 学会"改参数 → 看结果变化"的动手实验方法——这是理解机器学习最重要的一招。

## 2.1 安装 Python 3.12

**做什么**：Python 是运行本项目代码的语言。没有它，代码只是一堆文字。

> **注意版本**：本项目用到的 TensorFlow 只支持到 Python 3.12，**不要安装最新的 3.13**，否则后面装依赖会失败。请按下面的链接装 3.12。

1. 打开浏览器，访问 **https://www.python.org/downloads/release/python-3124/** ，滚动到页面下方的 "Files" 列表，点 **Windows installer (64-bit)** 下载安装包。
2. 双击安装包。**最重要的一步**：在安装窗口的最底部，**勾选 "Add python.exe to PATH"**（把 Python 加进环境变量）。勾完再点 "Install Now"。
3. 等它装完。

**成功标志**：按键盘 `Win + R`，输入 `cmd` 回车，会弹出一个黑色窗口（这叫"终端"或"命令行"）。在里面输入：

```
python --version
```

回车后如果显示 `Python 3.12.x`，就成功了。

> **如果显示"'python' 不是内部或外部命令"**：说明第 2 步的 "Add python.exe to PATH" 没勾上。重新运行安装包，选 "Modify"，把那个勾补上，装完再试。这是新手最常见的第一个坎，别慌。

## 2.5 打开终端，创建虚拟环境

**终端**就是那个黑底白字的命令行窗口，你用它给电脑下指令。**虚拟环境**是给本项目单独开的一个"隔离小房间"，把项目要用的软件包都装在里面，不跟其他项目打架。

1. 打开文件资源管理器，进入项目的 `源码` 文件夹。
2. 点击窗口最上方的**地址栏**（显示路径的那一条），删掉路径，输入 `cmd`，回车。会弹出一个终端窗口，而且它已经"站在"`源码` 这个文件夹里了。
3. 在终端里输入下面两条命令（输入完按回车，一条一条来）：

```
python -m venv venv
venv\Scripts\activate
```

**成功标志**：第二条命令回车后，终端最左边的提示符前面会出现 `(venv)`，例如：

```
(venv) D:\projects\QD05组_基于LSTM的洪水水位监测\源码>
```

这说明虚拟环境已激活。以后每次打开终端运行本项目，都要先激活它（重复第 1、2 步 + `venv\Scripts\activate` 这一条）。

## 2.6 安装依赖

**依赖**就是本项目用到的第三方软件包（TensorFlow、pandas 等）。别人已经写好的轮子，我们用 pip（Python 的"软件包安装工具"）把它们装进来。

1. （仍在这个终端里，提示符带 `(venv)`）先设置国内镜像，下载会快很多：

```
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

2. 安装依赖：

```
pip install -r requirements.txt
```

这一步要下载 TensorFlow 等大包（合计约 200MB），耐心等 5~15 分钟。终端里会不停滚动下载进度，这是正常的。

**成功标志**：最后几行出现 `Successfully installed ...` 字样，并且**没有任何红色字体的 Error**。

> 如果卡住或失败：先重新执行上一步的命令再试（网络偶尔会断）。如果提示某一行错误里带 `tensorflow`：删掉 `requirements.txt` 里的 `tensorflow-cpu` 这一行先不装，把其余装完，再单独执行 `pip install tensorflow-cpu==2.17.0`。

## 2.7 运行主程序

激动人心的时刻。在同一个终端里（提示符还是 `(venv)`），输入：

```
python train_lstm.py
```

回车后，程序开始工作。它会依次打印这些内容，**你可以对照着判断一切正常**：

| 你在终端里看到的内容 | 说明 |
|---|---|
| `Model input features: stage_ft, discharge_cfs, precipitation_mm` | 数据读取成功，三个特征都找到了 |
| `============ Training LSTM Model... ============` | 开始训练第一个模型（LSTM） |
| `Epoch 1/30`、`Epoch 2/30`…… | 训练进度。Epoch 是"把全部数据学一遍"，最多学 30 遍，如果成绩不再提高会提前停止（这叫"早停"，是好事） |
| `LSTM model saved to ...` | 第一个模型训练完成并保存 |
| `Training BiLSTM Model...` | 开始训练第二个模型（BiLSTM） |
| `Model Comparison Summary` + 一张 LSTM/BiLSTM 指标对比表 | 两个模型谁更准，直接打印出来 |
| `Training Complete!` | **全部完成！** |

**要跑多久？** 训练两个模型，每个最多 30 个 epoch（轮次）。实测一台普通笔记本（i5-11300H，无独立显卡）**一个 epoch 约 2 分钟**，两个模型全练满 30 轮需要约 2 小时；不过多数时候验证成绩在 10~25 轮就停止进步，早停机制会自动提前结束，**实际通常 30 分钟到 2 小时之间，视电脑速度而定**。训练期间电脑风扇会转、CPU 占用高、终端几秒才刷一行，都是正常的，中途别关窗口。

> **想先快速验证流程再正式训练**（推荐）：用 VS Code 打开 `源码/train_lstm.py`，把两处 `epochs=30` 临时改成 `epochs=3`、`patience=8` 改成 `patience=2`，运行一次（约 15~20 分钟）确认整条流程能走通，再把数字改回来正式训练。这就是"先小跑通、再大步走"的工程习惯。

**成功标志**：看到 `Training Complete!`，然后看产出。打开项目文件夹，会多出一个 `outputs` 文件夹，里面应该有这些文件：

| 文件 | 是什么 |
|---|---|
| `lstm_water_level_model.keras` | 训练好的 LSTM 模型（下次预测可以直接用，不用重新训练） |
| `bilstm_water_level_model.keras` | 训练好的 BiLSTM 模型 |
| `prediction_result.csv` / `prediction_result_bilstm.csv` | 测试集上每一小时的真实值 vs 预测值对照表 |
| `evaluation_metrics.csv` / `evaluation_metrics_bilstm.csv` | 每个预测小时的三个指标（MAE/RMSE/R²） |
| `model_comparison_metrics.csv` | 两模型总平均指标对比 |
| `future_forecast.csv` | 未来 24 小时水位预测 + 风险等级 |
| `prediction_plot.png` | 预测 vs 真实曲线图 |
| `risk_plot.png` | 最近水位 + 未来预测 + 警戒线图 |
| `model_comparison.png` | 两模型对比图 |

用看图软件打开三张 `.png`，你复现出来的图和 `data` 文件夹里上一届的成品图应该非常接近（因为程序固定了随机种子 42，结果可复现）。

**自检关键点**：打开 `outputs/model_comparison_metrics.csv`，R² 那一列应该在 **0.98 左右**（上一届跑出来是 LSTM 0.986 / BiLSTM 0.988）。如果你的 R² 也在这个量级，说明训练完全成功；如果 R² 只有 0.5 以下或文件是空的，去 2.9 找原因。

## 2.9 常见报错速查表

**遇到报错先深呼吸，来这张表里找。报错信息就看最后一行或倒数几行。**

| 报错信息（关键词） | 原因（人话） | 怎么办 |
|---|---|---|
| `No such file or directory: '...\\data\\cedar_rapids_stage_hourly.csv'` | 文件夹还没改名，程序找不到 `data` | 回到 2.4：把 `数据集` 改名为 `data`，重新运行 |
| `'python' 不是内部或外部命令` | 装 Python 时没勾 "Add to PATH" | 回到 2.1，重新运行安装包选 Modify 补勾 |
| `ModuleNotFoundError: No module named 'tensorflow'` | 没装依赖，或忘了激活虚拟环境 | 先看提示符有没有 `(venv)`，没有就执行 `venv\Scripts\activate`；有就执行 `pip install -r requirements.txt` |
| `pip install` 下载很慢或超时 | 网络问题 | 先执行 `pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple` 再装 |
| 带 `tensorflow` 的安装报错（红字一大片） | TensorFlow 与电脑环境不兼容 | 单独执行 `pip install tensorflow-cpu==2.17.0`；还不行就把报错最后几行拍照问老师 |
| `DLL load failed` 或 `动态链接库(DLL)初始化例程失败` | 电脑缺微软运行库，或 CPU 太老 | 下载安装微软 VC++ 运行库（微软官网搜 "Visual C++ Redistributable x64"）；电脑太老（2011 年以前）则换一台跑 |
| 训练跑着跑着窗口卡住不动 | 可能只是训练中，Epoch 之间无输出 | 耐心等 2 分钟；若超过 15 分钟毫无输出，按 `Ctrl + C` 中断，重跑一次 |

## 3.1 背景故事：为什么要预测水位

美国爱荷华州的 Cedar Rapids 市坐落在 Cedar River 河畔。2008 年 6 月，连降暴雨让这条河水位暴涨到 **31.12 英尺**，淹没了大片城区，造成数十亿美元损失。此后，当地一直在加强洪水监测。

美国地质调查局（USGS）在河边设了水文站（编号 05464500），每 15 分钟甚至更频繁地记录水位、流量等数据，全部公开在官网上。从 2008 年到 2026 年，这个站积累了 **16 万多条小时级记录**——这就是我们项目的"教材"。

项目的核心思想很简单：**洪水不是瞬间发生的，水位上涨有过程、有规律。如果模型能从历史里学会"前面 72 小时的水位走势如何影响未来 24 小时"，就能提前一天发出预警。** 提前 24 小时知道"水要涨过警戒线"，就能提前疏散、提前布防。

## 3.2 核心概念逐个讲（0 基础版）

### 3.2.1 时间序列

按时间先后排成的一串数字，就是时间序列。你每天记录体重、股市每天的收盘价、每小时的气温，都是时间序列。本项目的时间序列是"每小时的水位"。时间序列预测的意思就是：**根据前面的一段，猜后面的一段**。

### 3.2.2 特征与标签

- **特征（X）**：用来"猜"的线索。这里指过去 72 小时的水位、流量、降雨量。
- **标签（y）**：被猜的"答案"。这里指未来 24 小时的水位。

训练模型，本质上就是让模型反复练习"看 72 小时的线索 → 猜 24 小时的答案"，猜错了就调整自己，直到猜得够准。

### 3.2.3 滑动窗口：数据是怎么变成"练习题"的

18 年的数据是一条超长的序列。程序用一扇"72+24 小时宽的窗户"沿着时间一格一格滑过去，每次切出一组（线索 72 小时，答案 24 小时）：

```
时间轴：|---|---|---|---|---|---|---|---|---|---|---|
        [ 线索72小时 ][ 答案24小时 ]
              [ 线索72小时 ][ 答案24小时 ]
                    [ 线索72小时 ][ 答案24小时 ]
                    每滑 1 小时，得到一组新的练习题
```

这就是"滑动窗口"。16 万小时的数据，能切出 16 万多组练习题，教材非常厚。对应代码里的 `create_sequences()` 函数，切窗的两个数字 `WINDOW_SIZE = 72` 和 `FORECAST_HORIZON = 24` 就写在 `config.py` 里。

### 3.2.4 归一化：把不同量纲的数字拉到同一把尺子上

水位是 7 英尺，流量是 13000 立方英尺/秒，降雨是 2 毫米——三个数字大小差几个数量级。直接喂给模型，大数字会"淹没"小数字。归一化（这里用 MinMaxScaler）把每个特征都线性压缩到 0~1 之间：

```
原始值 → (原始值 - 最小值) / (最大值 - 最小值)  → 0~1 之间的数
```

模型在 0~1 的世界里学习，预测完再用同一套换算反推回真实的水位值。记住一个词：**"出去要换回来"**——代码里的 `inverse_stage()` 函数干的就是这件事。

### 3.2.5 训练集 / 验证集 / 测试集：教材、模拟考、真考

把 16 万组练习题分成三份：

- **训练集（约 68%）**：模型拿来"学习"的教材；
- **验证集（约 15%）**：每学一遍（一个 epoch）后做一次"模拟考"，用来观察模型有没有进步、什么时候该停止（早停就是看它）；
- **测试集（约 20%）**：从来没给模型看过的"高考真题"，学完之后用这份考卷打分。**分数只信这一份**，因为其他两份模型都见过了。

### 3.2.6 神经网络与 LSTM：模型本体是什么

**神经网络**可以粗略理解为一层层叠起来的"数字加工厂"：数字从输入层进去，经过中间的隐藏层不断变换组合，最后从输出层出来。工厂里的"旋钮"（叫权重，weights）一开始是随机拧的，每次猜错答案，就用"反向传播"算法把旋钮往对的方向拧一点。拧上几万次，就越来越准。这个拧旋钮的过程，就叫**训练**。

**普通网络的问题**：它看一个数据就忘一个，不知道"这一小时的水位比上一小时涨了"。**LSTM** 专门为"有顺序、有历史"的数据设计，它内部有一个"记忆通道"（cell state），能选择性地记住"三天前开始下雨"这种重要信息，忘掉"前天风大"这种无关信息——所以它对水位、股价、天气这类时间序列特别在行。**BiLSTM** 则让数据正着走一遍、倒着再走一遍，前后文都看，通常精度更高一点点（本项目实测 R² 0.988 vs 0.986，就是这么"一点点"）。

### 3.2.7 损失函数、优化器、epoch、batch：训练的四件套

- **损失函数（MSE，均方误差）**：衡量"猜得有多离谱"的尺子。预测值和真实值的差，平方后取平均。损失越小 = 越准。
- **优化器（Adam）**：负责"拧旋钮"的策略师，它决定每次往哪个方向拧、拧多大。
- **epoch**：把训练集完整学一遍。本项目最多 30 遍。
- **batch（128）**：不是一条一条学，而是每 128 条练习题凑成一包一起学，又快又稳。

### 3.2.8 过拟合、Dropout、早停：防止"死记硬背"

- **过拟合**：像学生把模拟卷答案背下来了，模拟考满分，真考一塌糊涂。模型在训练集上损失越来越小，但在验证集上反而变差——这就是背过头了。
- **Dropout（0.2）**：训练时每层随机"关掉"20% 的神经元，逼模型不能只靠某几个神经元死记，得学会更通用的规律。
- **早停（patience=8）**：连续 8 个 epoch 验证集成绩都没有提高，就自动停练。所以你不一定会看到 30 个 epoch 全部跑完——提前停下是模型在说"我学够了"。

### 3.2.9 三个评价指标：怎么给模型打分

假设某小时：真实水位 8.00 英尺，模型预测 7.90 英尺。

- **MAE（平均绝对误差）**：误差绝对值的平均。上面这次误差 0.10 英尺。单位就是英尺，最直观——"平均差 10 厘米水位"。
- **RMSE（均方根误差）**：误差平方后平均再开方。**对"离谱的大误差"惩罚更狠**，一个预测差 5 英尺，比五个预测各差 1 英尺严重得多。
- **R²（决定系数）**：0~1 之间的"拟合度"，**越接近 1 越好**。R²=0.98 可以粗浅理解为"模型解释了 98% 的水位变化"。注意 R² 可能为负——那说明模型还不如直接报平均值。

看这三个指标的规律：**预测越远的时刻，误差越大**。第 1 小时 R² 约 0.992，第 24 小时降到约 0.973——离现在越远，不确定性越大，这是所有时间序列预测的通性。

## 3.3 数据从哪来

项目用两个公开数据源（都在 `源码/download_usgs.py` 里下载）：

1. **USGS Water Services API**：美国地质调查局的水文数据库。两个参数代码：`00065` 是水位（gage height），`00060` 是流量（discharge）。下载下来的是"瞬时观测值"（十几分钟一条），代码按小时取平均，变成规整的小时级数据。
2. **Open-Meteo ERA5 Archive**：欧洲中期天气预报中心（ECMWF）的再分析数据，提供站点附近逐小时降雨量。

下载脚本做了三件重要的事：**小时聚合**（resample）、**缺失值插值**（interpolate，用前后值的连线补空洞）、**多源对齐**（join，按时间戳把水位和降雨拼到同一张表）。最终产出 `data/cedar_rapids_stage_hourly.csv`。

### 3.4.2 `train_lstm.py`：主程序，分六大块读

**第 1 块 · 读数据（main 函数开头）**

```python
data = pd.read_csv(CLEAN_DATA_PATH, parse_dates=["datetime"])
feature_columns = ["stage_ft", "discharge_cfs", "precipitation_mm"]
```

用 pandas 读 CSV 表格，并挑出三个特征列。`parse_dates` 让 pandas 把 `datetime` 列认成"时间"而不是普通文字。

**第 2 块 · 切窗口 + 归一化 + 划分数据集**

```python
x, y = create_sequences(scaled_features, scaled_stage)   # 滑动窗口切题
x_train, x_test = x[:train_size], x[train_size:]          # 前 80% 训练，后 20% 考试
```

`create_sequences()` 就是 3.2.3 讲的滑动窗口实现：一个 `for` 循环，从时间轴起点滑到终点，每滑 1 小时切一组（72 小时线索 + 24 小时答案）。

**第 3 块 · 搭模型**

```python
model = Sequential([
    Input(shape=(WINDOW_SIZE, n_features)),   # 入口：72 小时 × 3 个特征
    LSTM(64, return_sequences=True),          # 第一层 LSTM，64 个记忆单元，输出完整序列给下一层
    Dropout(0.2),                             # 随机关掉 20%，防过拟合
    LSTM(32),                                 # 第二层 LSTM，32 个单元
    Dropout(0.2),
    Dense(32, activation="relu"),             # 普通全连接层，把信息压成 32 个数字
    Dense(FORECAST_HORIZON),                  # 出口：一次性吐出未来 24 小时的预测
])
model.compile(optimizer=Adam(learning_rate=0.001), loss="mse")
```

`Sequential` 就是"积木排队"：数据按顺序穿过每一层。`compile` 是在宣布"用什么策略练（Adam）、用什么尺子打分（MSE）"。BiLSTM 版的搭法几乎一样，只是把 `LSTM` 包进了 `Bidirectional`——数据正反各走一遍。

**第 4 块 · 训练**

```python
early_stop = EarlyStopping(monitor="val_loss", patience=8, restore_best_weights=True)
lstm_model.fit(x_train, y_train, validation_split=0.15,
               epochs=30, batch_size=128, callbacks=[early_stop], verbose=2)
```

`fit` 就是"开练"。`validation_split=0.15` 从训练数据里再划 15% 当模拟考（验证集）；`restore_best_weights=True` 的意思是"停练后，把旋钮恢复到模拟考成绩最好的那一次"，而不是停在最后那圈。练完 `model.save(...)` 把旋钮存档，这就是 `.keras` 文件——以后预测不用重新练。

> **隐藏 bug 教学点（给好奇的你）**：这段代码在 BiLSTM 训练前**重新创建了一个早停回调**（`bilstm_early_stop`），而不是和 LSTM 共用同一个。因为早停回调内部会记住"到目前为止的最好成绩"——如果两个模型共用一个回调，BiLSTM 就会被拿来和 LSTM 的历史成绩比较，可能被错误地提前叫停。真实世界里这种"状态被共用"的 bug 非常常见，写代码时要留意：**凡是会"记住东西"的对象，一般不能随便复用。**（交付版本的代码已经修复了这个坑，你在练习 3 改 epochs 时会看到两个模型各有各的早停。）

**第 5 块 · 考试（评估）**

```python
predictions_lstm_scaled = lstm_model.predict(x_test, verbose=0)
```

让两个模型各自做 20% 的"高考真题"。注意预测值是归一化后的 0~1 数字，要用 `inverse_stage()` 换算回真实英尺，再逐小时算 MAE/RMSE/R²，写成 CSV。最后汇总成 LSTM vs BiLSTM 对比表——也就是你在终端里看到的 `Model Comparison Summary`。

**第 6 块 · 预测未来 + 画图**

拿最新的 72 小时当线索，让 LSTM 模型猜出未来 24 小时。然后 `classify_risk()` 把每个预测值和警戒线比较，标出风险等级，写进 `future_forecast.csv`。最后三个 `plot_*` 函数用 matplotlib 画出你在 1.2 看到的三张图（程序里第一行 `matplotlib.use("Agg")` 是让画图在"没有窗口的后台"也能工作）。

### 3.4.3 一个小细节：随机种子

`config.py` 里 `RANDOM_SEED = 42`，`train_lstm.py` 开头把它喂给 Python 和 numpy 的随机数发生器。神经网络训练里有随机性（旋钮的初始位置是随机的），固定种子后，同一台电脑上每次训练的结果都几乎一样。**这就是为什么你复现出的指标和图，和上一届的成品非常接近。**

## 3.5 风险分级是怎么算的

`classify_risk()` 函数就是一张"对照表"：

| 预测水位（英尺） | 等级 | 含义 |
|---|---|---|
| < 10.0 | normal | 正常 |
| 10.0 ~ 12.0 | action | 行动线：需关注 |
| 12.0 ~ 14.0 | minor | 轻度洪水 |
| 14.0 ~ 16.0 | moderate | 中度洪水 |
| ≥ 16.0 | major | 重度洪水 |

打开你的 `outputs/future_forecast.csv` 看最后一列 `risk_level`：本组数据预测都在 7~8 英尺，全是 `normal`——说明预测时段河道平静。**想想看**：如果拿 2008 年 6 月大洪水之前的数据训练，预测就会碰到 `major` 线。数据不同，结论就不同，这就是为什么我们要固定数据来源做实验。

## 3.7 动手改一改（最重要的练习）

> 规则：改之前记下原数值，改完运行，对比结果，**最后改回来**。每个练习都要问自己"为什么结果变了"。

**练习 1（入门）· 把预测时长从 24 小时改成 12 小时**
- 改哪：`config.py` 里 `FORECAST_HORIZON = 24` → `12`。
- 重新运行 `python train_lstm.py`。
- 预期看到：`future_forecast.csv` 只有 12 行；`evaluation_metrics.csv` 只有 12 行；模型最后一层输出从 24 个变成 12 个。
- 学到什么：**超参数**——不改代码逻辑，只改配置数字，程序行为就变了。这就是 `config.py` 存在的意义。

**练习 2（入门）· 把输入窗口从 72 小时改成 48 小时**
- 改哪：`config.py` 里 `WINDOW_SIZE = 72` → `48`，运行。
- 预期看到：训练样本数变多（窗口短，能切的题更多）；R² 大概率**略降**。
- 学到什么：给模型看的"历史"越短，信息越少，通常越难猜准——但训练更快。**窗口大小是"信息量"和"计算量"的权衡**。

**练习 3（进阶）· 把训练轮数砍到 5**
- 改哪：`train_lstm.py` 里两处 `epochs=30` → `epochs=5`，运行。
- 预期看到：训练飞快结束（1~2 分钟）；R² 明显下降（可能 0.9 以下）。
- 学到什么：**欠拟合**——练得太少，模型还没学会规律就被叫停。对比"练 30 轮"，体会"训练量"对精度的影响。

**练习 4（进阶）· 把警戒线挪一挪**
- 改哪：`config.py` 里 `RISK_THRESHOLDS_FT` 的 `"minor": 12.0` → `"minor": 9.0`，运行。
- 预期看到：`risk_plot.png` 里橙色虚线明显下移；`future_forecast.csv` 的 `risk_level` 从全 `normal` 变成 `action`（因为预测值 7~8 英尺已经超过新线）。
- 学到什么：**业务规则决定输出含义**。模型还是那个模型，阈值一变，预警结论完全不同——现实中的防灾决策就是这么调的，调严了误报多，调松了漏报多。

**练习 5（挑战）· 只用一个特征会怎样**
- 改哪：`train_lstm.py` 的 `main()` 里，把 `feature_columns = ["stage_ft", "discharge_cfs", "precipitation_mm"]` 改成只留 `["stage_ft"]`，运行。
- 预期看到：R² 下降（信息少了）；但模型输入变成 `(72, 1)`，能正常跑完。
- 学到什么：**特征工程的价值**——流量和降雨对水位预测是有贡献的"线索"。去掉线索，猜得就糙。真实项目中"选哪些特征"往往是成败关键。

> 全部做完后，记得把 `config.py` 和 `train_lstm.py` 改回原样，让项目保持"出厂状态"。
