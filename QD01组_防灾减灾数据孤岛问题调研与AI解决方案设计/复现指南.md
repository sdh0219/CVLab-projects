# QD01 · 防灾减灾数据孤岛问题调研与 AI 解决方案设计 · 零基础复现与使用指南

> 本指南面向完全没有编程基础的同学编写。你只需要会双击鼠标、会复制粘贴，跟着"复现手册"一步一步做，就能把项目跑起来；跑起来之后，再看"用户使用手册"了解这个项目到底在做什么、怎么用。
>
> **项目一句话**：把分散在不同机构、互不相通的防灾减灾数据（气象、地震、道路、人口……）汇总到一张表、一个平台里，让"数据孤岛"变成"数据大陆"。

# 第一部分 · 复现手册

## 1.1 你需要准备什么

| 需要的东西 | 说明 | 是否需要花钱 |
|---|---|---|
| 一台 Windows 电脑 | Windows 10 或 11，64 位 | 你已有 |
| Python 3.10 或更高版本 | 运行项目代码的"翻译官" | 免费 |
| VS Code 编辑器 | 看代码、写代码的工具 | 免费 |
| 本项目的文件 | 从本仓库下载 | 免费 |

## 1.2 安装 Python（约 5 分钟）

1. 打开浏览器，访问 Python 官方下载页：**https://www.python.org/downloads/**
2. 点击黄色的 **Download Python 3.x.x** 按钮，下载安装包
3. 双击下载好的安装包，**务必勾选最下方的 "Add python.exe to PATH"**（这一步最重要，漏勾会导致后面命令找不到 Python）
4. 点击 **Install Now**，等待安装完成
5. 验证是否成功：按 `Win + R`，输入 `cmd` 回车，在黑窗口里输入：

```
python --version
```

看到 `Python 3.x.x` 就说明安装成功了。

## 1.3 安装 VS Code（约 3 分钟）

1. 访问 VS Code 官网：**https://code.visualstudio.com/**
2. 点击蓝色的 **Download for Windows**，下载后双击安装，一路"下一步"即可

## 1.4 下载本项目文件

本项目完整文件已包含在仓库中，目录结构如下：

```
QD01组_防灾减灾数据孤岛问题调研与AI解决方案设计/
├── 源码/
│   ├── main.py              ← 数据融合主程序（先跑这个）
│   └── app.py               ← AI 融合平台（网页界面）
├── 数据集/
│   ├── raw_data/            ← 原始数据（气象/地震/道路/人口等）
│   ├── processed_data/      ← 已经清洗好的数据
│   └── metadata/            ← 数据说明
└── 文档/                    ← 技术方案与汇报材料
```

将整个 `QD01组_...` 文件夹放到你的电脑上，例如 `D:\projects\QD01组_...`（**建议路径不要有中文和空格**，避免一些程序报错；如果你的电脑只能用中文路径，绝大多数情况也能运行）。

## 1.5 安装项目依赖（约 5 分钟）

1. 打开"源码"文件夹，在地址栏输入 `cmd` 按回车（这样命令行会直接定位到这个文件夹）
2. 先创建虚拟环境（隔离环境，避免污染系统）并激活：

```
python -m venv venv
venv\Scripts\activate
```

看到命令行前面出现 `(venv)` 就说明环境激活成功。

3. 安装依赖：

```
pip install -r requirements.txt
```

> 国内网络下载慢的话，可以先执行：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple` 换成清华镜像再装。

## 1.6 运行数据融合主程序

在命令行中执行：

```
python main.py
```

等待运行完成，会看到类似输出：`融合完成，结果保存至 outputs/processed/`。

**预期产物**（在 `源码/outputs/processed/` 目录下）：
- `unified_monitoring_daily.csv` —— 监测数据总表（气象+水文逐日）
- `unified_hazard_events.csv` —— 灾害事件总表
- `unified_resource_points.geojson` —— 应急资源点位
- 若干张结果图（数据覆盖度、灾害分布等）

## 1.7 启动 AI 融合平台（网页版）

1. 确认命令行仍在 `源码` 目录且 `(venv)` 环境已激活
2. 执行：

```
streamlit run app.py
```

3. 浏览器会自动打开 **http://localhost:8501**，看到项目标题页即成功

**预期界面**：左侧是导航栏（数据总览 / 单类分析 / 融合分析 / 查询检索等页面），右侧是图表和表格。

## 1.8 复现完成了吗？

跑通 1.6 和 1.7 两步，本项目的复现就完成了。下面进入使用手册，弄明白"这是什么、怎么用"。

# 第二部分 · 用户使用手册

## 2.1 这个项目是做什么的

防灾减灾工作中，数据分散在很多地方：气象局有降雨数据、地震局有地震目录、测绘部门有道路和建筑数据、医院和消防有应急资源数据。这些数据**格式不一样、口径不一样、互不相通**，就像一座座孤岛，想综合起来分析非常困难。

本项目做的事情就是"搭桥"：

```
多个来源的原始数据
（气象 / 地震 / 灾害声明 / 道路 / 人口脆弱性 / 消防站 / 医院 / 滑坡）
        │  读取 + 清洗（统一日期、经纬度、字段名）
        ▼
   清洗后的标准数据
        │  按时间、空间融合
        ▼
   融合数据总表 + 可视化图表 + 网页交互平台
```

## 2.2 输入与输出

**输入**（`数据集/` 目录）：
| 数据 | 来源 | 说明 |
|---|---|---|
| 气象日汇总 | NOAA 国家海洋大气局 | 温度/降水/风速等 |
| 灾害声明 | FEMA 联邦应急管理署 | 历史灾害事件记录 |
| 地震目录 | USGS 美国地质调查局 | 地震位置、震级 |
| 道路数据 | TIGER 人口普查局 | 道路几何与等级 |
| 人口脆弱性 | SVI 疾控中心 | 社区脆弱性指数 |
| 应急资源 | 消防站/医院公开数据 | 救援能力点位 |

**输出**（`源码/outputs/`）：
- 4 张融合数据表（监测总表、事件总表、资源点位、道路统计）
- 1 套可视化图（数据覆盖度图、灾害时空分布图等）
- 1 个网页平台（Streamlit，浏览器交互）

## 2.3 网页平台功能说明（对应 app.py）

启动平台后，左侧导航依次是：

| 功能 | 点哪里 | 能看到什么 |
|---|---|---|
| 数据总览 | 左侧"数据总览" | 各类数据量、时间跨度、覆盖度统计表 |
| 单类数据分析 | 选择数据类别 | 该类数据的图表（如地震震中分布） |
| 多源融合分析 | "融合分析"页 | 灾害事件与监测数据的联合展示 |
| 智能查询 | "查询检索"页 | 输入关键词/时间/区域筛选数据 |

操作很简单：**点左侧菜单 → 看右侧图表**。所有图表都可下载为图片。

## 2.4 业务逻辑流程（完整版）

```
真实多源数据（8 类） ──► 缺失的数据自动生成模拟兜底（标记 SIMULATED_FALLBACK）
        │
        ▼
字段清洗：统一日期格式、经纬度、灾害类型、数据来源
        │
        ▼
数据融合：监测数据表 / 灾害事件表 / 应急资源表 / 人口脆弱性表 / 道路统计表
        │
        ▼
可视化 + Streamlit 网页平台（供决策者直观查看）
```

如果某类真实数据下载失败，程序不会崩溃，而是**自动生成同格式的模拟数据并打上标记**，保证流程能完整跑通——这也是工程上"兜底"思想的体现。

## 2.5 常见问题

| 问题 | 原因与解决 |
|---|---|
| `python` 不是内部或外部命令 | 装 Python 时没勾 PATH，重装并勾选，或重启命令行 |
| 网页打不开 | 确认命令行停留在 `源码` 目录、环境已激活；重新执行 `streamlit run app.py` |
| 缺某个数据文件报错 | 程序会自动生成模拟兜底数据；若仍报错，确认 `数据集/` 目录完整 |
| 端口被占用 | 换端口运行：`streamlit run app.py --server.port 8502` |
