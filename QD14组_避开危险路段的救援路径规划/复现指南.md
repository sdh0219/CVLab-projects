# 第一部分 · 项目导览

## 1.1 这个项目是做什么的

**一句话**：在一张真实的城市道路网上，用 Dijkstra 最短路算法规划救援路线——一次按"距离最短"算，一次按"避开危险路段"算，把两条路线画在地图上对比。

背景是真实的：北京及周边发生过 1679 年三河-平谷大地震、2012 年"7·21"特大暴雨。灾害发生时，救援车辆如果按导航走"最短路"，可能正好穿过塌方、积水的路段。这个项目做的事情是：**把历史灾害的位置（经纬度+影响半径）叠到道路网上，落进灾害圈的路段标成"危险路段"并加大它的通行代价**，然后重新算路——救援车宁愿多绕几公里，也不穿过危险区。

## 1.2 先看成品（不用动手，双击打开就行）

在 `数据集\结果输出\` 文件夹里已经放好了上一届运行的成品图，先打开看看：

| 文件（每个场景子文件夹里） | 是什么 |
|---|---|
| `amap_earthquake\route_map.png` | 地震场景：两条路线对比图，彩色虚线圆=历史地震影响圈 |
| `amap_flood\route_map.png` | 暴雨场景：同样两条路线的对比 |
| `path_comparison.csv` | 两条路线的量化对比表（距离/代价/经过几条危险路段），用 Excel 打开 |

> 重点看：**安全路线明显绕开了危险圈，但距离更长**——这就是本项目的核心结论：安全是有代价的，算法帮你量化这个代价。

## 1.3 输入与输出：这个项目"吃什么、吐什么"

**吃进去（输入）**：每个场景文件夹（如 `数据集\amap_earthquake\`）里 4 类文件：

| 文件 | 内容 |
|---|---|
| `nodes.csv` | 路网的所有路口（编号、经纬度、名称） |
| `edges.csv` | 所有路段（起点、终点、长度 km、危险类型 normal/flood/collapse、拥堵系数、是否可通行） |
| `scenario.json` | 场景设定：起点 N001、终点 N002、各种危险的"代价放大倍数" |
| `disaster_events.csv` / `road_disaster_mapping.csv` | 历史灾害事件清单、哪条路被哪个灾害影响的对照表 |

**吐出来（输出）**：运行后在指定的输出目录生成 6 个文件——`edge_weights.csv`（每条路段算好的安全权重）、`path_results.json`（两条路线详情）、`path_comparison.csv`（对比表）、`route_map.png` / `route_map_clean.png` / `route_map_context.png`（三张地图）。

## 1.4 业务流程图：整个项目在跑什么

```
真实道路网（高德 API 抓取的北京路网，几百条路段）
        │
        ▼
叠加历史灾害缓冲区（地震/暴雨位置 + 影响半径 → 圆圈）
        │  落进圈的路段标记 danger_type（flood/collapse）
        ▼
给每条路段算"安全权重"：
   安全权重 = 距离 × 危险放大倍数 × (1 + 0.6×拥堵) + 固定罚项
        │
        ▼
Dijkstra 算两次：
   ① 按原始距离算 → 最短路线
   ② 按安全权重算 → 安全路线
        │
        ▼
画图对比 + 输出量化表格
```

## 1.5 用到哪些技术（每个词先用"人话"认识一下）

| 技术名词 | 人话解释 |
|---|---|
| Python | 编程语言，本项目全部用它写 |
| 图（Graph） | 路网的数学抽象：路口=点（node），路段=边（edge） |
| Dijkstra 算法 | 经典的"最短路"算法：从起点一圈圈往外扩，第一次碰到终点时的路径就是最短的 |

| Pillow | Python 的画图库，本项目用它直接把路线画到地图上（不用装专业的 GIS 软件） |

# 第三部分 · 理解手册

## 3.1 背景故事：危险的路，是算出来的

灾害响应里有个反直觉的事实：**导航软件给的"最快路线"在灾时可能恰恰是最危险的路线**。2012 年北京"7·21"暴雨中，多辆汽车被困在下沉式立交桥的积水区——那些位置在平时就是最顺畅的近路。

本项目用两个真实历史灾害做例子：
- **1679 年三河-平谷 8 级地震**（影响半径约 2.7 km 的区域标记为塌方风险）；
- **2012 年北京 7·21 暴雨**（大范围区域标记为积水风险）。

作者事先用高德地图 API 抓取了北京城区的真实路网（几百个路口、几百条路段，含每条路的形状折线），再把灾害缓冲区叠上去。**你要复现的，是"叠加之后怎么算路"这一步**——这也是整个项目最有技术含量的部分。

## 3.2 核心概念逐个讲

### 3.2.1 图（Graph）：路网的数学抽象

把每个路口编号成 N001、N002……（**点**），每条可通行的路是连接两个点的**边**，边上挂三个关键属性：`distance`（长度 km）、`danger_type`（normal/congestion/flood/collapse）、`congestion`（拥堵程度 0~1）。数据集里的 `nodes.csv` + `edges.csv` 合起来就是一张图。

### 3.2.2 Dijkstra：为什么它保证最短

想象从起点往水里丢一块石头，波纹一圈圈向外扩散——波纹第一次碰到终点时，走过的就是最短路径。Dijkstra 算法就是这个过程：维护一个"已确定最短距离的点"集合，每次从中转代价最小的点往外扩展一步，用 `heapq`（优先队列）保证每次取的都是当前最小的。**只要所有边权都是正数，它算出的就是全局最优**——不是猜的，是数学上可证明的。

### 3.2.3 边权设计：本项目的灵魂

`compute_safe_weight`（rescue_planner.py 第 120-125 行）：

```
安全权重 = 距离 × 风险放大倍数 × (1 + 0.6 × 拥堵) + 固定罚项
```

风险放大倍数查 `scenario.json`：normal=1.0（正常）、congestion=1.4（拥堵）、flood=2.2（积水）、collapse=4.0（塌方）。翻译成人话：**塌方路段的"心理距离"是实际距离的 4 倍**——救援决策者宁可绕 4 倍的路也不想走塌方区，算法把这种偏好写成了数字。

### 3.2.4 算法与代价解耦

注意程序里 Dijkstra 只写了一遍（`dijkstra()` 函数），跑两次靠的是传入不同的 `edge_cost` 函数：mode="distance" 时用原始距离，mode="safe" 时用安全权重。**这是很漂亮的工程设计**：算法本身不动，换个"代价的定义"就能回答不同的问题（还可以自己加"最少红绿灯"模式）。

### 3.2.5 缓冲区叠加：灾害怎么变成路网标记

`tools/create_disaster_scenarios.py` 做的事：读历史灾害的经纬度和影响半径 → 判断每条路段的折线坐标是否落进圆内 → 是则把该边的 `danger_type` 改成对应类型，并写进 `road_disaster_mapping.csv`（含证据链接，可溯源）。这一步是"空间分析"的最简版本。

## 3.4 动手改一改（最重要的练习）

> 规则：改之前记下原数值，改完运行，对比结果，**最后改回来**。

**练习 1（入门）· 把塌方的代价调大**
- 改哪：`数据集\amap_earthquake\scenario.json` 里 `"collapse": 4.0` → `"collapse": 10.0`，重跑 2.4 的命令。
- 预期：安全路线可能绕得更远（更怕塌方了）；最短路线**完全不变**（它根本不看风险）。
- 学到：参数只影响"安全模式"，加深"两种代价函数独立"的理解。

**练习 2（入门）· 换一对起终点**
- 改哪：`scenario.json` 里 `start_node` / `target_node`（换成 nodes.csv 里任意两个编号，如 N005 → N030）。
- 预期：两条路线都变，图上重新画线。
- 学到：图算法的通用性——换需求不用改代码，换数据就行。

**练习 3（进阶）· 加一种新的危险类型**
- 改哪：`scenario.json` 的 `risk_factors` 里加 `"fire": 3.0`；把 `edges.csv` 里某几行的 `danger_type` 改成 `fire`。
- 预期：程序照常运行，这些边获得 3 倍代价。
- 学到：数据驱动的系统怎么扩展——加类型不用改代码。

**练习 4（挑战）· 打印路线的逐步导航**
- 改哪：在 main 里拿到路径节点序列后，用 `edges.csv` 的 `road_name` 列把路线翻译成"沿 XX 路 → 转 YY 路"的文本导航。
- 学到：图路径 → 人类可读信息的转换，实际的导航软件就是这么做最后一步的。

## 3.5 怎么读结果

打开 `path_comparison.csv`：

| 列 | 含义 | 怎么解读 |
|---|---|---|
| `total_distance` | 路线总长（km） | 安全路线更长（26.8 vs 19.9）——绕路的代价 |
| `total_cost` | 按安全权重算的总代价 | 安全路线代价更"便宜"——这就是选它的理由 |
| `dangerous_edge_count` | 经过几条危险边 | 注意：安全路线 7 条 vs 最短路线 4 条？看下一列 |
| `danger_types` | 危险边类型明细 | 安全路线的 7 条全是 **congestion（拥堵）**，最短路线里有 **collapse（塌方）** |

**这个细节是最好的教学点**：安全 ≠ 危险数为零，而是**危险结构不同**——宁可堵车，不赌塌方。

## 3.6 思考题
