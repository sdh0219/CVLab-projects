# 第一部分 · 项目导览

## 1.1 这个项目是做什么的

**一句话**：雨量计（测量降雨量的自动仪器）出的数据经常有毛病——卡住不动、突然报个天文数字、出现负值——这个项目用**物理规则 + 机器学习**两套办法把异常找出来、修正掉，并量化证明"清洗前后预警质量差别巨大"。

为什么重要：暴雨预警靠雨量数据触发。如果雨量计卡滞（漏记暴雨）或虚假翻斗（多记 10 倍雨量），预警就会**漏报**（人民生命危险）或**误报**（狼来了效应）。本项目的杀手锏是结尾那组数字：**原始数据算出的月总降雨量比真值虚高 17.6 倍，清洗后误差只有 -0.32%**——这就是数据清洗的业务价值。

**吃进去（输入）**：本项目**不需要任何现成数据文件**——程序发现数据缺失时会自动生成一套"合成雨量数据"（30 天 × 每 10 分钟一条 = 4320 条），并按固定随机种子（2024）注入 7 类典型异常。因为注入异常时保留了"真值标签"，程序才能给自己打分。

# 第三部分 · 理解手册

## 3.1 背景：雨量计的七宗罪

翻斗式雨量计是最普及的自动测雨仪器：每接满 0.1mm 雨水翻一次斗。它的典型故障构成了一部"错误类型大全"：

| 异常类型 | 现象 | 物理原因 |
|---|---|---|
| missing 缺失 | 时间轴断档 | 供电/通信中断 |
| negative 负值 | 雨量为负 | 传感器故障 |
| spike 尖峰 | 突然报 999 | 故障哨兵值/雷击 |
| stuck 卡滞 | 连续 1 小时读数恒定不变 | 翻斗被卡/虫网堵塞 |
| spurious 虚假翻斗 | 无雨时段蹦出 0.1~0.2mm | 振动/露水误触发 |
| 重复行 | 同一时刻出现两条 | 记录重发 |
| 乱序 | 时间戳前后颠倒 | 缓存乱序写入 |

本项目把它们全部注入合成数据，逐一检测——**这是一份"数据质量问题教科书"**。

## 3.2 核心概念逐个讲

### 3.2.1 合成数据 + 受控注入（generate_data.py）

用泊松过程模拟降雨事件、伽马分布抽样峰值、钟形廓线展开——生成的"真值"数据有真实的统计特性。然后按剧本注入异常，同时记下每个异常的位置（真值标签）。**这是整个项目的方法论基石：有了真值，一切修复效果都可量化**。种子 RANDOM_SEED=2024 保证你和上一届生成完全相同的数据。

### 3.2.2 稳健 Z 分数：为什么不用普通标准差

普通离群分 = (x-均值)/标准差。问题是：**一个 999 的尖峰会把均值和标准差都拉跑**，其他异常反而显得"正常"。稳健版用中位数和 MAD（中位数绝对偏差）：`z = (x - median) / (1.4826 × MAD)`——中位数和 MAD 对极端值几乎免疫。再加"绝对量级 + 孤立跳变"双门槛，保护真实暴雨峰值不被误杀（实测误报 0）。

### 3.2.3 修正管线的工程取舍（cleaning.py 四步曲）

1. **掩膜**：把异常点标记为缺失（先隔离再处理）；
2. **插值**：时间线性插值，**最多连续补 6 个点（1 小时）**——更长的缺口不臆造数据，保守置 0 并打 `filled_longgap` 标记；
3. **物理约束**：负值截断为 0，重新按 0.1mm 量化（仪器物理分辨率）；
4. **平滑**：3 点中值 + 3 点均值平滑滤掉残余毛刺。

每一步都体现同一个哲学：**修数据要保守，宁可留可疑标记，不可编造**。

### 3.2.4 规则与 ML 的混合决策（hybrid_qc.py）

规则命中 → 直接判 correct（置信 0.86）；ML 单独命中 → 只进 manual_review（0.62，等人复核）；规则+ML 双命中 → 高置信 0.95；≥20mm 的暴雨峰值 → 保护豁免（绝不删）。**人话：物理规则说了算，模型只提意见**——因为规则可解释、可审计，黑盒模型在关键决策上只能辅助。

### 3.2.5 孤立森林与 LSTM 自编码器（ml_anomaly.py）

- **孤立森林**：随机选特征、随机选切割值，把数据切成孤岛。异常点离群，平均切几刀就孤立了（路径短）；正常点要切很多刀（路径长）。不需要标签，适合"不知道异常长什么样"的场景。
- **LSTM 自编码器**：只用**正常数据**训练"压缩→还原"网络；测试时还原误差大的就是没见过的异常模式。窗口 18 步（3 小时），适合捕捉"时间模式异常"（数值正常但节奏不对）。

### 3.2.6 预警影响分析（warning_impact.py）

把技术指标翻译成业务语言：按 10min/16mm、1h/30mm、3h/50mm、24h/100mm 四档预警阈值，统计原始数据 vs 清洗数据的误报/漏报事件数。**数据质量直接等于预警可信度**——这是给非技术的人看的成绩单。

- 改哪：`anomaly_detection.py` 里注释掉负值检测那段，重跑 baseline。
- 预期：召回率下降（21 个负值异常漏掉），F1 降低。
- 学到：这就是"消融实验"——用数据证明每个组件的贡献。

**练习 3（进阶）· 把插值上限从 6 改成 60**
- 改哪：`config.py` 的 `INTERP_LIMIT = 6` → `60`。
- 预期：`filled_longgap` 的点减少，但总雨量误差**可能变差**——长缺口线性插值会引入系统偏差。
- 学到："补得多"不等于"补得对"，保守修复的价值。

**练习 4（挑战）· 给预警阈值做敏感性分析**
- 改哪：`warning_impact.py` 的 `WARNING_THRESHOLDS`，把 1h 阈值从 30 改成 20/25/40 各跑一次，对比误报/漏报。
- 学到：预警阈值设定的政策权衡（太严扰民，太松害人）。

## 3.5 怎么读结果

- `evaluation.json`：P 100%（抓的全是真异常）/ R 97.45%（真异常抓回 97.45%）/ F1 98.71%。**为什么召回不到 100%？** 有 7 个异常藏在规则盲区（如紧挨真实暴雨的轻微 spurious）——诚实的技术报告会说清楚边界。
- `method_comparison.csv`：规则 / 孤立森林 / LSTM-AE / 两两组合 / 三合一，各自 P/R/F1。看"规则+IF"与"规则单独"差多少，体会 ML 的边际贡献。
- `fig4`（累计雨量）：原始线 13222mm 是被尖峰异常抬起来的；清洗线 708.6 与真值 710.9 几乎重合。
- `hybrid_qc_decisions.csv`：每条异常的最终处置（correct/manual_review）与置信度。
