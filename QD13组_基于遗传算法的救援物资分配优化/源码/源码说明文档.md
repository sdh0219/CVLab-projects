# 源码说明文档

本文档说明「基于遗传算法的救援物资分配优化」项目 `源码/` 目录下的代码结构与实现逻辑。**第一部分重点解释 `code/` 文件夹中的 Python 后端核心源码**，涵盖物资分配模型、遗传算法编码、适应度函数与约束处理四大模块。

---

## 1. `code/` 目录总览

`code/` 为项目 **Python 后端核心**，负责数据加载、遗传算法优化、结果分析与前端数据导出。

```
code/
├── main_universal.py        # 通用版主程序与物资分配模型（推荐入口）
├── main.py                  # 河南洪灾专用版主程序（含 Matplotlib 绘图）
├── ga_enhanced.py           # 遗传算法增强算子与优化主循环
├── data_loader.py           # 通用数据加载与校验
├── export_for_frontend.py   # 导出 JSON 供 Vue 前端可视化
├── config.json              # 通用版运行配置
├── config_README.md         # config.json 字段说明
├── test_universal.py        # 通用版功能快速验证
└── test_data.py             # 数据加载测试
```

### 1.1 模块关系

```
config.json / 数据包
       │
       ▼
 data_loader.py ──► UniversalAllocationModel (main_universal.py)
                           │
                           ├── 适应度函数 / 约束修复
                           │
                           └── GAEnhancedMixin (ga_enhanced.py)
                                    │
                                    ▼
                           export_for_frontend.py ──► frontend/public/data/results.json
```

### 1.2 两个主程序版本

| 文件 | 适用场景 | 说明 |
|------|----------|------|
| `main_universal.py` | 多数据集、可配置参数 | 通过 `config.json` 切换河南洪灾基准数据与两组模拟数据，自动适配规模 |

两者共享同一套 **物资分配模型逻辑** 与 **遗传算法算子**（`GAEnhancedMixin`），差异主要在数据入口与是否内置绘图。

## 2. 四大核心模块说明

### 2.1 物资分配模型

**实现类**：`UniversalAllocationModel`（`main_universal.py`）、`AllocationModel`（`main.py`）

模型将救援物资调度问题建模为 **多仓库向多受灾点多物资类型的分配优化**。

#### 决策变量（编码载体）

个体 `individual` 为三维实数数组，形状：

```
(num_warehouses, num_points, num_materials)
```

即：`individual[w, p, m]` 表示仓库 `w` 向受灾点 `p` 调运物资 `m` 的数量。

#### 输入数据

| 字段 | 含义 |
|------|------|
| `disaster_points` | 受灾点属性（坐标、人口、伤亡、紧急系数等） |
| `warehouses` | 仓库属性（坐标、库存、车辆数、单车容量等） |
| `distance_matrix` | 仓库到受灾点的距离矩阵 |
| `road_conditions` | 道路通行状况（0~1，影响运输成本） |
| `transport_time` | 运输时间矩阵 |
| `demand` | 受灾点各物资需求量 |
| `inventory` | 仓库各物资库存量 |
| `urgency_weights` | 受灾点紧急程度权重 |
| `material_weights` | 各物资类型权重 |

#### 运力计算

```python
max_transport_capacity(w) = vehicles[w] × vehicle_capacity[w]
```

表示仓库 `w` 的最大可运输总量。

#### 初始解生成策略

`generate_individual()` 混合两种启发式，再经 `repair()` 修复为可行解：

1. **紧急优先初始化**（70%）：`_generate_individual_urgency_first()`  
   按紧急程度、路况、距离和需求规模分配各仓库运力预算。
2. **路况分配初始化**（30%）：`_generate_individual_road_based()`  
   按道路通行因子比例分配，用于增加种群多样性。

#### 方案分析

`analyze_solution(individual)` 输出满足率、公平性、紧急得分、时间效率、运输成本、车辆使用情况等指标，供控制台打印与前端展示。

### 2.2 遗传算法编码

本项目采用 **实数直接编码**：染色体即分配矩阵本身，无需额外解码步骤。

#### 种群初始化

```python
generate_population(size)  # 生成 size 个经 repair 的可行个体
```

#### 遗传算子（`ga_enhanced.py`）

| 算子 | 方法 | 策略说明 |
|------|------|----------|
| 选择 | `tournament_select()` | 锦标赛选择，从可行个体中多次随机抽样取最优 |
| 交叉 | `crossover_enhanced()` | 按仓库块交换父代片段，或按受灾点切片交换 |
| 变异 | `mutate_adaptive()` | 对紧急程度高、满足率低的受灾点加大扰动概率 |
| 局部搜索 | `local_search()` | 从满足率高处向低处小幅调拨，贪心提升适应度 |
| 精英保留 | `optimize_enhanced()` | 每代保留精英个体，并始终追踪全局最优 |

#### 优化主循环特性

`optimize_enhanced()` 在标准遗传算法框架上增加了：

- 初始种群前若干个体做局部搜索，提高起点质量
- 全局最优个体每代强制保留，适应度曲线单调不降
- 停滞检测：连续多代无改进时自动提高变异率，帮助跳出局部最优

`UniversalAllocationModel.optimize()` 从 `config.json` 读取 `pop_size`、`generations`、`mutation_rate` 等参数后调用该主循环。

### 2.3 适应度函数

**入口方法**：`fitness(individual)`（`main_universal.py`）

采用 **多目标加权求和** 的综合评价方式。不可行个体直接返回 `-1.0` 作为惩罚。

#### 五个子目标

| 子目标 | 计算函数 | 含义 |
|--------|----------|------|
| 物资满足率 | `calculate_satisfaction_rate()` | 各受灾点按物资权重加权的需求满足程度 |
| 运输成本 | `calculate_transport_cost()` | 运量 × 距离 ÷ 路况，路况差则成本更高 |
| 公平性 | `calculate_fairness()` | 各点满足率方差的倒数，方差越小越公平 |
| 紧急程度 | `calculate_urgency_score()` | 满足率与紧急权重的加权和 |
| 时间效率 | `calculate_time_efficiency()` | 总运输时间的倒数形式 |

#### 默认权重

```python
{
    'satisfaction': 0.35,
    'transport_cost': 0.15,
    'fairness': 0.2,
    'urgency': 0.2,
    'time_efficiency': 0.1
}
```

权重来源优先级：数据文件中的 `objective_weights` > 模型默认值。可通过 `set_objective_weights()` 动态修改。

> **说明**：`config.json` 中 `objectives` 段描述了各目标的权重与开关，但当前代码主要从数据字典读取权重；修改 `config.json` 中的目标权重不一定自动生效，需在数据文件或代码中设置。

---

### 2.4 约束处理

采用 **修复算子（Repair）** 策略：交叉、变异后对个体调用 `repair()`，通过等比缩放恢复可行性。

#### 三类硬约束

| 约束 | 修复方法 | 规则 |
|------|----------|------|
| 库存约束 | `_enforce_inventory_limit()` | 某仓库某物资出库总量不超过库存 |
| 需求约束 | `_enforce_demand_limit()` | 某受灾点某物资接收总量不超过需求 |
| 车辆约束 | `_enforce_vehicle_limit()` | 某仓库总出库量不超过车辆总运力 |

`repair()` 依次执行上述三步并迭代 5 轮，使约束逐步收敛。

#### 可行性检查

`is_feasible(individual)` 检查：

- 库存是否超限
- 车辆使用数是否超过仓库可用车辆数

需求上限主要由 `repair()` 保证；路况对运输的影响作为 **软约束** 体现在运输成本目标中，而非硬截断。

## 5. 关键设计说明

### 5.1 为何使用 Mixin 继承

`GAEnhancedMixin` 将选择、交叉、变异、主循环与业务模型分离：

- `main.py` / `main_universal.py` 专注 **问题建模与评价**
- `ga_enhanced.py` 专注 **进化搜索策略**

便于在不改动模型的情况下替换或增强遗传算子。

### 5.2 约束处理策略选择

本项目使用 **修复算子** 而非罚函数，优点是：

- 种群中大部分个体保持可行
- 交叉变异后可快速恢复约束满足
- 适应度 `-1.0` 仅用于极端不可行情况

### 5.3 多目标处理方式

五个目标通过加权求和合并为单目标适应度，适合遗传算法直接优化。各子目标在 `analyze_solution()` 中仍可单独输出，便于结果分析与可视化对比。

## 6. 已知限制与注意事项

1. **文档与实现差异**：根目录 `README.md` 中曾描述「轮盘赌选择」「单点交叉」，实际实现为 **锦标赛选择** 与 **仓库块交叉**，以本文档与 `ga_enhanced.py` 为准。
2. **配置项未完全接入**：`config.json` 中部分 `objectives` / `constraints` 开关尚未驱动运行时逻辑。
3. **代码重复**：`main.py` 与 `main_universal.py` 中模型部分逻辑相近，维护时需注意同步。
4. **大规模数据耗时**：`export_for_frontend.py` 对 80×12 规模数据集运行 GA 耗时较长，属正常现象。
