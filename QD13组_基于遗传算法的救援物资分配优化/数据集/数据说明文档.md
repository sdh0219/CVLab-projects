# 数据包说明文档

本文档为数据包**唯一说明文档**，介绍数据来源、目录结构、原始数据、处理后数据、字段含义及预处理流程。

---

## 1. 数据包概述

本数据包为「基于遗传算法的救援物资分配优化」项目提供模型输入数据，包含 **1 组基准数据** 与 **2 组扩展模拟数据**：

| 数据集 | 目录 | 规模 | 数据性质 |
|--------|------|------|----------|
| 河南洪灾基准数据 | `processed_data/` | 6 受灾点 × 3 仓库 × 3 物资 | 真实案例整理 |
| 大规模洪涝数据 | `dataset_01_large_scale/` | 80 × 12 × 3 | 规则模拟生成 |
| 复杂场景数据 | `dataset_02_complex_scenario/` | 15 × 6 × 5 | 规则模拟生成 |

---

## 2. 目录结构与各文件夹作用

```
数据包/
├── 数据说明文档.md                 # 本文档（唯一数据说明）
│
├── raw_data/                       # 【原始数据】河南洪灾案例的原始记录
│   ├── henan_disaster_raw_data.py  #   受灾点、仓库、物资、道路等原始定义
│   ├── *.csv                       #   兖州区应急物资储备清单（格式参考）
│   └── *.json                      #   国家数据中心应急物资数据集元信息
│
├── processed_data/                 # 【处理后数据】基准数据集（模型默认输入）
│   └── henan_disaster_processed_data.py
│
├── dataset_01_large_scale/         # 【处理后数据】大规模模拟数据集
│   ├── metadata.json               #   数据集规模与统计摘要
│   └── processed_data/
│       └── processed_data.py       #   模型可直接加载的数组数据
│
├── dataset_02_complex_scenario/    # 【处理后数据】复杂场景模拟数据集
│   ├── metadata.json               #   数据集规模与统计摘要
│   ├── scenario_config.json        #   复杂场景约束与灾害类型描述
│   └── processed_data/
│       └── processed_data.py
│
├── config_examples/                # 【配置示例】切换数据集用的 config.json 模板
│   ├── config_large_scale.json
│   └── config_complex_scenario.json
│
└── tools/                          # 【工具脚本】模拟数据生成器
    └── generate_datasets.py
```

### 各文件夹说明

| 文件夹 | 作用 |
|--------|------|
| `raw_data/` | 存放河南洪灾基准案例的**原始数据**，包含受灾点统计、仓库库存、道路状况及外部参考文件，是基准数据预处理的输入来源。 |
| `processed_data/` | 存放基准案例经预处理后的**模型输入数据**，供 `main.py` / `main_universal.py` 直接加载。 |
| `dataset_01_large_scale/` | 大规模洪涝模拟数据集，侧重验证算法在**高维度、大规模**场景下的可扩展性。 |
| `dataset_02_complex_scenario/` | 复杂多灾害模拟数据集，侧重验证**多物资、异构仓库、复杂通行条件**等约束建模能力。 |
| `config_examples/` | 提供切换不同数据集时`config.json`的配置模板，不含实际数据。 |
| `tools/` | 数据生成脚本，可重复生成 `dataset_01` 与 `dataset_02` 的模拟数据。 |

> 两组扩展模拟数据**无独立 raw_data 目录**，由 `tools/generate_datasets.py` 按规则直接生成处理后数据。

## 4. 原始数据说明

原始数据仅针对**河南洪灾基准案例**，存放于 `raw_data/henan_disaster_raw_data.py`。

### 4.1 受灾点原始数据 `disaster_points_raw`

| 字段索引 | 字段名 | 类型 | 含义 |
|---------|--------|------|------|
| 0 | 受灾点ID | 整数 | 唯一标识（1–6） |
| 1 | 经度 | 浮点数 | 地理经度（°） |
| 2 | 纬度 | 浮点数 | 地理纬度（°） |
| 3 | 受灾人口 | 整数 | 受影响人口（人） |
| 4 | 死亡失踪人数 | 整数 | 伤亡统计（人） |
| 5 | 紧急转移安置人数 | 整数 | 转移安置人数（人） |
| 6 | 房屋损坏数量 | 整数 | 受损房屋（间/套） |
| 7 | 紧急系数 | 整数 | 紧急程度（1–5 级） |

### 4.2 仓库原始数据 `warehouses_raw`

| 字段索引 | 字段名 | 类型 | 含义 |
|---------|--------|------|------|
| 0 | 仓库ID | 整数 | 唯一标识 |
| 1 | 经度 | 浮点数 | 仓库经度 |
| 2 | 纬度 | 浮点数 | 仓库纬度 |
| 3 | 仓库名称 | 字符串 | 储备库名称 |
| 4–6 | 物资1–3库存 | 整数 | 饮用水、方便面、帐篷库存量 |
| 7 | 车辆数量 | 整数 | 可用运输车辆数 |
| 8 | 车辆容量 | 整数 | 单车最大载重（单位） |

### 4.3 物资原始定义 `materials_raw`

| 字段 | 含义 |
|------|------|
| 物资ID | 唯一标识 |
| 物资名称 | 饮用水、方便面、帐篷 |
| 单位 | 瓶 / 箱 / 顶 |
| 人均需求量 | 需求估算系数 |
| 优先级 | 调度优先等级 |

### 4.4 道路状况原始数据 `road_conditions_raw`

矩阵形式，行对应仓库、列对应受灾点：

| 取值 | 含义 |
|------|------|
| 1.0 | 道路畅通 |
| 0.5–0.9 | 拥堵或部分受损 |
| 0.2–0.4 | 严重受阻或中断 |

## 5. 数据预处理过程

### 5.1 基准数据（河南洪灾）

```
公开统计公报 / 开源仓库 / 原始记录
        ↓
① 受灾点清洗：提取 6 个重点受灾区县，统一为 8 列属性数组
        ↓
② 仓库整理：确定 3 个省级储备库坐标与库存，补充车辆信息
        ↓
③ 需求估算：按受灾人口与紧急系数计算三类物资需求量
   · 饮用水需求 ≈ 受灾人口 × 2
   · 方便面需求 ≈ 受灾人口 × 0.5
   · 帐篷需求   ≈ 受灾人口 × 0.02（结合紧急系数修正）
        ↓
④ 距离计算：由经纬度计算仓库到受灾点的球面距离（公里）
        ↓
⑤ 道路评估：结合灾后路况设定道路完好系数矩阵
        ↓
⑥ 时间估算：运输时间 = 距离 ÷ (基准速度 × 道路系数)
        ↓
⑦ 权重生成：紧急程度权重、物资权重、目标函数权重
        ↓
输出 → processed_data/henan_disaster_processed_data.py
```

**处理要点：**

- 原始伤亡数据在部分记录中存在数量级差异，按统计公报口径统一修正（如郑州死亡失踪人数由 112 修正为 112,132）。
- 需求矩阵独立导出为 `demand`，库存矩阵独立导出为 `inventory`，与 `disaster_points` / `warehouses` 主数组分离，便于模型直接读取。

### 5.2 大规模数据（dataset_01_large_scale）

```
设定场景参数（80 受灾点 / 12 仓库 / 3 物资）
        ↓
① 在黄淮流域范围内生成受灾点与仓库经纬度
② 按人口规模（8,000–120,000）与紧急系数（1–5）生成受灾点属性
③ 按「人口 × 物资系数 × 紧急修正」计算需求矩阵
④ 按总需求 55%–75% 比例分配各仓库库存
⑤ 随机生成车辆数量（25–90）与单车容量（80–160）
⑥ Haversine 公式计算距离矩阵
⑦ 根据距离与随机扰动生成道路状况与运输时间
⑧ 由紧急系数归一化得到 urgency_weights，写入 metadata.json
        ↓
输出 → dataset_01_large_scale/processed_data/processed_data.py
```

### 5.3 复杂场景数据（dataset_02_complex_scenario）

```
设定 15 个具名受灾点与 6 个异构仓库
        ↓
① 为每个受灾点指定灾害类型、通行等级、配送时间窗
② 为每个仓库指定物资专长、冷链/越野等特殊属性
③ 按五类物资（饮用水、食品、帐篷、药品、发电设备）计算需求矩阵
④ 按仓库专长设定异构库存
⑤ Haversine 公式计算距离矩阵
⑥ 道路系数 = 基础路况 − 灾害类型惩罚 − 通行等级惩罚
⑦ 运输时间 = 距离 ÷ (基准速度 × 道路系数)
⑧ 复杂约束描述写入 scenario_config.json
        ↓
输出 → dataset_02_complex_scenario/processed_data/processed_data.py
```

**重新生成命令：**

```bash
cd 数据包/tools
python generate_datasets.py
```

## 6. 处理后数据说明

处理后数据以 Python 模块形式存储，供遗传算法模型直接 `import` 加载。

### 6.1 通用输出变量

| 变量名 | 维度 | 含义 |
|--------|------|------|
| `disaster_points` | (N, 8) | 受灾点属性数组 |
| `warehouses` | (M, K) | 仓库属性数组（K 随物资种类变化） |
| `demand` | (N, T) | 物资需求矩阵 |
| `inventory` | (M, T) | 仓库库存矩阵 |
| `distance_matrix` | (M, N) | 仓库到受灾点距离（公里） |
| `road_conditions` | (M, N) | 道路完好系数（0.2–1.0） |
| `transport_time` | (M, N) | 预计运输时间（小时） |
| `urgency_weights` | (N,) | 紧急程度权重 |
| `material_weights` | (T,) | 物资重要性权重 |
| `objective_weights` | dict | 多目标优化权重 |
| `disaster_points_info` | dict | 受灾点扩展描述（名称、灾害类型等） |
| `warehouses_info` | dict | 仓库扩展描述（专长、运力等） |
| `metadata` | dict | 数据集元信息与统计摘要 |

### 6.2 各数据集规模

| 数据集 | 受灾点 | 仓库 | 物资 | 受灾人口 | 总需求 | 总库存 |
|--------|--------|------|------|----------|--------|--------|
| 基准（河南洪灾） | 6 | 3 | 3 | 1,947,900 | 4,908,708 | 451,544 |
| 大规模 | 80 | 12 | 3 | 5,169,540 | 17,078,456 | 11,675,647 |
| 复杂场景 | 15 | 6 | 5 | 878,600 | 3,555,974 | 989,000 |

### 6.3 复杂场景扩展字段

`dataset_02_complex_scenario` 在 `disaster_points_info` 和 `warehouses_info` 中包含额外描述：

**受灾点扩展字段：**

| 字段 | 含义 |
|------|------|
| `disaster_type` | 灾害类型（洪水、内涝、山体滑坡、堰塞湖、复合灾害） |
| `access_level` | 通行等级（良好 / 一般 / 较差 / 极差 / 中断） |
| `delivery_time_window_hours` | 配送时间窗（小时） |
| `priority_tier` | 响应优先级（一级 / 二级 / 三级） |
| `special_needs` | 特殊需求（如药品优先、发电保障） |

**仓库扩展字段：**

| 字段 | 含义 |
|------|------|
| `specialties` | 仓库物资专长 |
| `cold_chain` | 是否具备冷链能力 |
| `all_terrain_vehicles` | 是否具备山地越野运力 |

## 7. 字段说明（模型输入）

### 7.1 受灾点数组 `disaster_points`

| 列索引 | 字段 | 类型 | 含义 |
|--------|------|------|------|
| 0 | ID | int | 受灾点唯一编号 |
| 1 | 经度 | float | 地理经度（°） |
| 2 | 纬度 | float | 地理纬度（°） |
| 3 | 受灾人口 | int | 受影响人口（人） |
| 4 | 死亡失踪人数 | int | 伤亡统计（人） |
| 5 | 转移安置人数 | int | 紧急转移人数（人） |
| 6 | 房屋损坏数量 | int | 受损房屋（间） |
| 7 | 紧急系数 | int | 紧急程度（1–5 级） |

### 7.2 仓库数组 `warehouses`

| 列位置 | 字段 | 含义 |
|--------|------|------|
| 0 | ID | 仓库唯一编号 |
| 1 | 经度 | 仓库经度 |
| 2 | 纬度 | 仓库纬度 |
| 3 至 3+T−1 | 物资库存 | 各物资类型库存量（T 为物资种类数） |
| 倒数第 2 列 | 车辆数量 | 可用运输车辆数 |
| 最后 1 列 | 车辆容量 | 单车最大载重（单位） |

### 7.3 矩阵类字段

| 变量 | 维度 | 单位 | 含义 |
|------|------|------|------|
| `demand[i, m]` | 受灾点 × 物资 | 单位 | 受灾点 i 对物资 m 的需求量 |
| `inventory[w, m]` | 仓库 × 物资 | 单位 | 仓库 w 中物资 m 的库存 |
| `distance_matrix[w, p]` | 仓库 × 受灾点 | 公里 | 仓库 w 到受灾点 p 的运输距离 |
| `road_conditions[w, p]` | 仓库 × 受灾点 | 0.2–1.0 | 道路通行系数，越小越难通行 |
| `transport_time[w, p]` | 仓库 × 受灾点 | 小时 | 预计运输耗时 |

### 7.4 权重字段

| 变量 | 含义 |
|------|------|
| `urgency_weights` | 各受灾点紧急程度权重，由紧急系数归一化得到 |
| `material_weights` | 各物资类型在满足率计算中的权重 |
| `objective_weights` | 多目标优化权重（满足率 35%、成本 15%、公平性 20%、紧急程度 20%、时间效率 10%） |

### 7.5 模型约束与数据字段对应

| 约束 | 规则 | 相关字段 |
|------|------|----------|
| 库存约束 | 仓库发出量 ≤ 库存 | `inventory` |
| 需求约束 | 受灾点接收量 ≤ 需求 | `demand` |
| 车辆约束 | 运输总量 ≤ 车辆数 × 单车容量 | `warehouses` 末两列 |

## 8. 数据使用方式

修改 `源码/code/config.json` 中的 `disaster_points_file` 即可切换数据集：

| 数据集 | 配置路径 |
|--------|----------|
| 基准 | `../../数据包/processed_data/henan_disaster_processed_data.py` |
| 大规模 | `../../数据包/dataset_01_large_scale/processed_data/processed_data.py` |
| 复杂场景 | `../../数据包/dataset_02_complex_scenario/processed_data/processed_data.py` |

也可直接复制 `config_examples/` 下的配置模板使用。

## 9. 数据使用声明

1. **基准数据**来源于公开灾害统计与学术研究，用于教学与科研演示。

3. 如需使用完整原始数据集，可向国家基础学科公共科学数据中心申请获取。
