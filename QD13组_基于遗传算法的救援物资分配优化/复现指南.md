# 第一部分 · 项目导览

## 1.1 这个项目是做什么的

**一句话**：以 2021 年河南"7·20"特大暴雨为背景，用**增强型遗传算法**求解"3 个仓库 → 6 个受灾点 × 3 类物资"的分配方案——同时照顾满足率、运输成本、公平性、紧急程度、时间效率五个目标——并配一个 Vue3 + ECharts 可视化大屏。

物资分配是救援的"最后一公里"难题：郑州 115 万人待安置，饮用水、方便面、帐篷怎么从 3 个储备库分出去？人工拍脑袋很难同时平衡"别浪费运力"和"别饿着任何人"。**优化算法就是把这堆互相打架的目标变成一道可计算的数学题**。

## 1.4 业务流程图

```
读入数据：受灾点(需求/紧急系数) + 仓库(库存/车辆) + 距离/路况
        │
        ▼
初始化种群（100 个"分配方案"，七成按紧急优先启发式生成）
        │
        ▼  每一代：
   ① 修复约束（库存/需求/车辆上限，等比缩放逼近可行域）
   ② 算适应度（五目标加权：满足率/成本/公平/紧急/时间）
   ③ 锦标赛选择 + 精英保留（前 10% 直接晋级）
   ④ 交叉（按仓库块交换，0.85）+ 自适应变异 + 贪心局部搜索
        │  迭代 50 代（停滞 6 代自动提升变异率破局）
        ▼
输出最优方案 → 3 张图 + results.json → 前端大屏展示
```

## 1.5 用到哪些技术（人话版）

| 技术名词 | 人话解释 |
|---|---|
| 优化问题 | 在一堆可行方案里找"最好"的那个 |
| 遗传算法（GA） | 模仿生物进化：一堆随机方案→择优杂交→随机变异→一代代变好 |
| 种群/个体/基因 | 全体候选方案/单个方案/方案里的一个数 |
| 适应度 | 给方案打的综合分——分高的活下来 |
| 多目标加权 | 五个目标各定权重加成一个总分 |
| 约束修复（repair） | 随机方案常违反库存上限，按比例缩放回可行域 |
| 锦标赛选择 | 随机抽 3 个方案，最好的当父母——比"纯排名"更抗早熟 |
| 精英保留 | 每代最好的 10% 不参与杂交直接晋级，保证不倒退 |
| 自适应变异 | 卡住了就加大变异力度（0.1→最高 0.35），有进展就减小 |
| Flask / Vue3 / ECharts | 后端小服务 / 前端框架 / 图表库 |

- 理解**多目标问题**怎么压成单目标（以及权重即价值观）；
- 见识 GA + 局部搜索的**模因算法**混合策略；
- 体验一次"Python 后端 + Vue 前端"的完整小系统。

# 第三部分 · 理解手册

## 3.1 背景：河南"7·20"暴雨的物资难题

2021 年 7 月 20 日，郑州一小时降雨 201.9mm（大陆小时雨量纪录），全省数千万人受灾。灾后 72 小时是救援黄金期：饮用水、食品、帐篷从郑州/洛阳/开封的储备库运往各受灾点，但车辆有限、道路受损、各点紧迫程度不同。**分配方案差一点，可能就有人多等一天**——这类问题在运筹学里叫"多目标资源分配"，是遗传算法的经典应用场景。

## 3.2 核心概念逐个讲

### 3.2.1 方案怎么编码成"染色体"

一个方案 = 一张三维表：`分配量[仓库][受灾点][物资]`。河南案例是 3×6×3=54 个数——就是 54 个"基因"。初始种群 100 个方案，其中 70% 用"紧急优先"启发式生成（先满足紧急系数高的点），30% 用"路况优先"生成——**比纯随机起点好得多**，好的初始化能省一半进化时间。

### 3.2.2 五目标加权适应度（main.py L370-390）

```
适应度 = 0.35×满足率 + 0.15×成本倒数 + 0.20×公平性 + 0.20×紧急加权满足率 + 0.10×时间倒数
```

公平性 = 1/(1+各点满足率的方差)——方差越大（有人撑死有人饿着）分越低。**权重就是价值观**：把公平从 0.2 调到 0.4，算法立刻变成"均贫富"模式。不可行解直接判 -1 分淘汰。

### 3.2.3 约束修复：非法方案怎么办（L392-399）

随机杂交出的方案经常超库存（一个仓库运出超过储备）。repair 做法是：对每个超限维度**等比缩放**，三轮迭代逼近可行域。比"罚函数"（在分数上扣分）更直接可靠——保证活下来的方案都是可执行的。

### 3.2.4 锦标赛选择 + 精英保留（ga_enhanced.py）

- **锦标赛（k=3）**：随机抽 3 个方案，最好的当亲本。不至于像"只选前几名"那样基因太单一；
- **精英保留（10%）**：每代最优方案直接晋级下一代，且全局历史最优永远占 0 号位——适应度曲线单调不降的保证。

### 3.2.5 自适应变异 + 贪心局部搜索（模因算法）

- 变异不是乱改：紧急度高、缺口大的受灾点获得更高变异概率（最高 0.5），且 70% 的变异方向是"加量"——**变异也带启发式**；
- 连续 6 代没进步（停滞）→ 变异率 ×1.8（上限 0.35）强行破局；
- 每代再对个体做**贪心调拨**：从满足率高的点匀 15% 给低的点，分数涨就接受——GA（全局搜索）+ 局部搜索（精细打磨）= 模因算法。

## 3.4 动手改一改

**练习 1（入门）· 改目标权重**
- 改哪：`code\config.json` 里 objective_weights，把 fairness 0.2→0.4、satisfaction 0.35→0.15，重跑 main_universal.py。
- 预期：各点满足率更平均，但总体满足率可能下降。
- 学到：权重即价值观，多目标优化的本质。

**练习 2（入门）· 砍掉局部搜索**
- 改哪：config.json 里 local_search_steps 4→0，重跑。
- 预期：收敛变慢、最终适应度略低。
- 学到：用消融验证每个组件的贡献。

**练习 3（进阶）· 种群规模实验**
- 改哪：pop_size 100→30 和 →200 各跑一次，对比 fitness_history 曲线。
- 预期：小种群收敛快但容易卡在局部最优；大种群稳但慢。
- 学到：探索 vs 利用（exploration vs exploitation）的权衡。

**练习 4（挑战）· 固定随机种子**
- 改哪：main.py 开头加 `import numpy as np; np.random.seed(42)`。
- 预期：两次运行结果完全一致。
- 学到：可复现性——实验科学的基本要求（原项目没固定种子，是个真实的工程疏漏）。

## 3.5 怎么读结果

- **fitness_history.png**：三条曲线（历史最优/当代最优/平均）。平均线逐渐贴近最优线=种群收敛；最优线阶梯状上升=精英保留在起作用。
- **satisfaction_comparison.png**：看哪个受灾点满足率最低——为什么？通常是距离远+紧急系数低被算法"牺牲"了。**这里藏着伦理讨论：效率最优 ≠ 公平。**
- **大屏雷达图**：五个维度的达标程度一眼看清。
- **热力图**：哪个仓库承担了主要运力？和它的车辆数/库存匹配吗？

## 3.6 思考题

1. 适应度里成本除以 10000、时间除以 1000，为什么要这样归一？不归一会怎样？
2. 遗传算法保证找到全局最优吗？不保证的话，怎么提高可信度？（提示：多次独立运行）
3. 紧急系数 4.0 的郑州和 1.0 的县城，满足率差多少是"可接受的"？
4. 如果道路中断（distance_matrix 某些值不可用），模型该怎么改？
