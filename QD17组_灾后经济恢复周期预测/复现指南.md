# 第一部分 · 项目导览

## 1.1 这个项目是做什么的

**一句话**：把美国 1990-2026 年的地震目录、重大地震损失记录、各州 GDP 数据拼成一张大表，用**随机森林**和**梯度提升树（GBDT）**两种机器学习模型，预测"一场地震后，当地经济需要几年才能恢复到震前水平"（0/1/2/3/>3 年，五分类）。

回答的是防灾领域一个很硬的问题：**地震的直接破坏看得见，但经济恢复要多久？** 答案决定了保险定价、财政储备、重建规划。模型给出的答案是一组概率（比如"62% 概率当年恢复，25% 概率 1 年"），并且能告诉你**哪些因素最重要**（震级？人口？经济结构？）。

跑通后你还会得到：混淆矩阵图、特征重要性 Top20 图、预测分布图、两个模型的对比指标。

## 1.4 业务流程图

```
三个公开数据源（地震目录 + 损失记录 + 州 GDP）
        │  按州、按年对齐，拼成"每场地震一行"的大表
        ▼
构造标签：灾后实际 GDP 几年回到震前水平？
   灾前1年GDP为基线 → 当年回到=0年 → ... → 3年未回=4(>3年)
        │
        ▼

        │
        ▼

        │
        ▼
训练两个模型对决：随机森林 vs 梯度提升树
        │
        ▼
评估（accuracy / macro_f1 / 混淆矩阵）+ 特征重要性分析 + 生成 PPT
```

## 1.5 用到哪些技术（人话版）

| 技术名词 | 人话解释 |
|---|---|
| 监督学习 / 分类 | 给机器带答案的练习题，学会后预测"属于哪一类"（这里：恢复要几年） |
| 特征 / 标签 | 输入的线索（震级、GDP…）/ 要预测的答案（恢复年数） |
| 随机森林（RF） | 种几百棵决策树，每棵只看部分数据，最后投票——"三个臭皮匠"集成法 |
| 梯度提升树（GBDT） | 一棵接一棵地种，每棵专门纠正前面所有树犯的错——"错题本"式提升 |
| 数据泄漏 | 考试题提前混进练习册，成绩虚高——机器学习第一大坑 |
| 分组切分 | 同一个"州-年"的数据不能一半在训练、一半在测试（它们太像了） |
| 类别不均衡 | 0 年（马上恢复）的样本特别多，模型会偷懒全猜多数类 |
| 混淆矩阵 | 行=真实类别、列=预测类别的计数表，一眼看出模型在哪类上翻车 |
| 特征重要性 | 每个特征对预测的贡献度打分 |
| macro_f1 | 对每个类别一视同仁的平均 F1，类别不均衡时比 accuracy 更公道 |

# 第三部分 · 理解手册

## 3.1 背景：地震的"第二重灾难"是经济

地震的房子塌了看得见，但经济系统的恢复是慢变量：企业停产、人口外流、投资信心受挫。学界用"实际 GDP 回到灾前水平所需年数"度量恢复速度。这个项目用公开数据第一次让你亲手回答：**恢复快慢，由什么决定？**

数据三源：**USGS**（地震的物理参数）、**NOAA**（历史损失的人文参数）、**BEA**（美国经济分析局的州级年度 GDP，含分行业）。三张表按"州 × 年"缝在一起——这步数据工程本身就是真实数据科学的日常。

## 3.2 核心概念逐个讲

### 3.2.1 标签是怎么"造"出来的（prepare 脚本 L159-167）

预测目标不是现成字段，而是从 GDP 序列里**计算**出来的：取灾前 1 年实际 GDP 为基线，逐年往后看——当年≥基线=0 年，第 2 年回到=1 年……3 年还没回=4（>3 年）。**把回归问题转化成 5 分类**，标签客观、可复算。这一步教学价值极高：监督学习里最难的往往不是模型，是"答案从哪来"。

### 3.2.2 数据泄漏与分组切分（train 脚本 L105-145）

朴素随机切分会有漏洞：加州 2019 年的两场地震，特征几乎一样（同州同年同经济背景），若一场在训练集、一场在测试集，等于**考题在练习册里见过**——成绩虚高。本项目用 GroupShuffleSplit 按"州_年"整组切分，还循环试 1000 个随机种子挑出"训练/测试都覆盖全部 5 类"的切分。**这是本项目最值得学的工程细节。**

### 3.2.3 随机森林 vs GBDT：两种集成哲学

- **RF（Bagging）**：500 棵树并行独立生长，每棵只喂部分数据、只看部分特征，最后投票。**降低方差**——臭皮匠们各犯各的错，投票抵消。
- **GBDT（Boosting）**：300 棵树串行生长，第 k 棵专门拟合前 k-1 棵的残差（还没学会的部分）。**降低偏差**——错题本越记越厚。
- 同数据、同切分跑两个脚本对比——这是最好的"控制变量实验"。

### 3.2.4 类别不均衡与 macro_f1

0 年恢复（多数类）样本占大头。两个对策：训练时 `compute_sample_weight("balanced")` 给少数类更大的"话语权"；评估时看 macro_f1（每类 F1 平均）而非 accuracy。**经验法则：类别不均衡时，只报 accuracy 的模型都要警惕。**

### 3.2.5 特征重要性的 OneHot 还原（train 脚本 L93-170）

类别特征（如"州"）经 OneHot 编码后炸成上百列，直接看重要性排名会被稀释。脚本把编码后的列**按原始特征名聚合求和**再排名——所以 feature_importance_top20.png 里看到的是"州"、"震级"这样的原始名次。数据处理与可解释性的实用细节。

## 3.4 动手改一改

**练习 1（入门）· 缩小数据集看稳定性**
- 改哪：① 的 `--limit 1500` 改成 `800`，重跑 ①②。
- 预期：macro_f1 下降（数据少了）；多跑几次感受波动。
- 学到：数据量与模型表现的 scaling 关系。

**练习 2（入门）· 调 GBDT 树的深度**
- 改哪：② 加参数 `--max-depth 5`（默认 3）重跑。
- 预期：训练准确率上升，macro_f1 可能反降（过拟合了）。
- 学到：容量-过拟合的直觉。

**练习 3（进阶）· 对比"切分方式"**
- 改哪：② 加参数 `--split-method stratified`（普通分层切分，不分组）。
- 预期：**准确率虚高、macro_f1 也"变好"**——但这是泄漏假象！
- 学到：亲手制造一次数据泄漏，比背十遍概念都记得牢。

**练习 4（挑战）· 特征消融**
- 改哪：把特征清单 txt 里的行业占比相关特征删掉几行，重跑 ②。
- 预期：macro_f1 微降，特征重要性排名重新洗牌。
- 学到：特征工程的边际贡献分析。

## 3.5 怎么读结果

- **confusion_matrix.png**：对角线=预测对的。看第 4 类（>3 年才恢复）那一行——大概率大面积落到 0 类（被多数类吞了），这就是不均衡的杀伤力。
- **feature_importance_top20.png**：看前几名是什么。经验上"年份/州/震级/GDP 规模"会霸榜——想想哪些是"真正的因果"，哪些只是"相关"。
- **test_predictions.csv**：每行有 prob_class_0 到 prob_class_4 五个概率。挑一条概率很集中（如 0.9）和一条很犹豫（0.3/0.3/0.2）的样本对比——模型也有"拿不准"的时候，概率告诉你它有多确定。

## 3.6 思考题

1. "灾前 1 年 GDP 为基线"——如果地震发生在 2008 年金融危机期间，这个基线公不公平？
2. 为什么不用回归直接预测"恢复天数"？五分类丢了什么信息？
3. 特征重要性高 ≠ 因果关系。举一个本项目里可能"相关但非因果"的特征。
4. 类加权让少数类权重变大，可能带来什么副作用（提示：误报）？

## C. 环境版本与验证记录

本指南全部命令已在以下环境真机执行验证（2026-08-23）：

- Windows 10 19045，CPU i5-11300H；Python 3.12.4
- pandas 3.0.5 / scikit-learn 1.9.0 / matplotlib 3.11.1 / joblib 1.5.3 / python-pptx 1.0.2
- 实测：mklink 建链接 → ①②③④ 全部一次跑通，退出码 0
- 实测指标（种子 42）：GBDT accuracy 0.831 / macro_f1 0.403；RF accuracy 0.915 / macro_f1 0.423；PPT 13 页生成成功
- 全流程耗时约 6 分钟（CPU）

**最后验证日期：2026-08-23。**

## D. 数据出处

- USGS ComCat（fdsnws API）：美国 M4.5+ 地震目录，1990-2026
- NOAA NCEI Significant Earthquake Database：重大地震损失记录
- U.S. Bureau of Economic Analysis (BEA)：SAGDP 州级年度 GDP（总量与分行业）
- 均为公开数据，仅用于教学与学术研究。
