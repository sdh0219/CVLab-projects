# 第一部分 · 项目导览

## 1.2 这个项目是做什么的

**一句话**：一条纯本地运行的 Python 流水线——先用"设备授权"机制解密加密的秦岭山区灾害数据，再读取 12 层地理栅格（坡度/岩性/土壤湿度…）做 **AHP 层次分析法易发性评估**，按国标四级预警模拟，为高风险村落匹配最近避难所生成转移计划，最后输出 6 张专题图和逐像元数据表。

"零死亡"是山区防灾的最高目标：泥石流从启动到摧毁村落可能只有十几分钟，**提前知道"哪个山村危险、雨下多大要撤、撤到哪里"**就是保命方案的全部。本项目把这套逻辑做成了可计算的桌面推演。

> 本项目还有一个特别的"课程设计"：数据文件是 AES 加密的，必须先用 keygen 生成"授权文件"才能解密运行——这是作者用来演示**数据授权与加密机制**的教学环节（3.2.2 详解）。

## 1.5 用到哪些技术（人话版）

| 技术名词 | 人话解释 |
|---|---|
| GeoTIFF / 栅格 | 带地理坐标的图像：每个像素是一个位置的测量值（如坡度） |
| AHP 层次分析法 | 让专家给因子两两比较打分，算出一组权重——主观经验的数学化 |
| 加权叠加 | 每层乘权重再相加，得到综合评价图——GIS 最经典操作 |
| 因子标准化 | 把不同量纲（度/米/指数）都压到 0~1 的危险分 |
| AES-256-CBC | 对称加密标准；CBC 是一种加密模式 |
| 设备指纹 / 授权文件 | 用机器 MAC+主机名生成"身份证"，授权只能在这台机器用一次 |
| 反向因子 | 数值越大越不危险的因子（如植被覆盖度） |
| Haversine/欧氏距离 | 球面/平面两点距离（小范围用欧氏×111km/度 即可） |

## 1.6 做完这个项目，你将学会什么

- 理解 **GIS 栅格分析**的核心套路：标准化 → 加权 → 叠加 → 分级；
- 会用 AHP 把专家经验转成可计算的权重，并理解它的主观性；
- 理解对称加密、密钥封装、HMAC 签名三件套（以及"密钥写在源码里=演示级安全"的局限）；
- 体会"预警阈值"和"转移规划"怎么从国标文件变成代码；
- 学会读栅格数据（rasterio）并做像元级统计。

# 第三部分 · 理解手册

## 3.1 背景：秦岭山区的泥石流防御战

秦岭北麓（西安南部）沟壑纵横，汛期短时强降雨常触发泥石流。防御体系的核心三问：
1. **哪里危险？**（易发性评估——静态，由地形地质决定）
2. **雨下多大要撤？**（预警分级——动态，由降雨驱动）
3. **撤到哪里？**（转移规划——预案，村对应避难所）

本项目用 10 个环境因子回答问题 1，用国标四级雨量阈值回答问题 2，用最近邻匹配回答问题 3——**三问连成"零死亡"闭环**。

## 3.2 核心概念逐个讲

### 3.2.1 AHP + 栅格加权叠加（本项目主菜）

10 个因子按专家权重加权（config.json）：

| 因子 | 权重 | 方向 |
|---|---|---|
| 坡度 slope | **0.25** | 越陡越危险 |
| 岩性 lithology | 0.15 | 松散岩层危险 |
| 土壤湿度 | 0.12 | 越湿越危险（润滑+增重） |
| 高程 dem | 0.10 | **反向**：越高人越少/汇水面积小 |
| 土地利用 | 0.10 | 裸地>耕地>林地 |
| 植被指数 ndvi | 0.10 | **反向**：植被固土 |
| 侵蚀沉积量 | 0.08 | 越多越危险 |
| 地形湿度指数 | 0.05 | 越大越危险 |
| 有机碳 | 0.03 | **反向** |
| 土壤 pH | 0.02 | **非线性**：偏离中性越远越危险 |

每个因子先按 config 里的 `factor_ranges` 标准化到 0~1（注意方向！），再逐像元加权求和 → 易发性指数 → 按阈值 [0.2,0.4,0.6,0.8] 分五级。**这就是"专家经验 + 空间数据 = 风险地图"的全部魔法。**

### 3.2.2 加密与授权链（keygen.py / key_manager.py）

流程：`SHA256(固定密钥材料)` → 数据解密密钥 → 用 `SHA256(MAC+主机名)` 前 16 字节 XOR 封装 → HMAC 签名 → 写入 `.license`（限用 1 次）。运行时反向校验：文件在→有效→没用过→签名对→机器对 → 发密钥 → 计数+1。

教学价值：一次看到**对称加密、密钥封装、防篡改签名、单次授权**四个概念。**局限也要看清**：密钥材料明文写在源码里，拿到源码就能解密——这是课程演示级安全，真实系统密钥绝不能进代码库。

### 3.2.3 栅格-矢量叠加

人口点位（经纬度）怎么查它落在哪个风险等级？栅格有地理变换参数（每像元的经纬度步长）：`列号 = (经度-左边界)/像元宽`，行号同理——一行代码把连续坐标变成网格下标。**GIS 里最常用的"点取栅格值"操作。**

### 3.2.4 最近邻转移规划

高风险聚落 TOP20，每个在低风险避难所里找**欧氏距离最近**的：`距离km = √(Δ经度²+Δ纬度²) × 111`（1 度≈111km），再除以步速 4.8km/h 得徒步时长。小范围内欧氏近似够用（对比：QD15 项目用了更精确的 Haversine）。

### 3.2.5 四级预警阈值（config.json warning_rules）

蓝 15/50 → 黄 30/100 → 橙 50/150 → 红 70/200（1h/24h 雨量，mm），对应"加强监测→准备转移→紧急转移→全面撤离"。这些数字改自国标《GB/T 28592-2012 降雨量等级》和气象行业标准《QX/T 487-2019》，**业务规则源自权威标准**——工程里的好习惯。

## 3.4 动手改一改

**练习 1（入门）· 调高坡度权重**
- 改哪：config.json 的 ahp_weights.slope 0.25→0.40（其他等比缩小让总和=1），重跑。
- 预期：fig1 里陡坡区域颜色更红。
- 学到：AHP 权重的敏感度——专家打分差一点，地图大变样。

**练习 2（入门）· 降低红色预警阈值**
- 改哪：config.json warning_rules.red 的 70→50（1h），重跑。
- 预期：fig4 红色触发频率变高（更容易达到撤离条件）。
- 学到：预警阈值是"漏报 vs 误报"的政策旋钮。

**练习 3（进阶）· 改变风险分级阈值**
- 改哪：config.json risk_thresholds [0.2,0.4,0.6,0.8]→[0.3,0.5,0.7,0.9]。
- 预期：高风险聚落数量变少，转移计划变短。
- 学到：分级边界对"有多少人需要转移"的直接影响。

**练习 4（挑战）· 加一个新因子**
- 改哪：找一张同范围的"距河流距离"栅格放入 processed_data，在 main.py ② 节仿照现有因子加标准化与权重。
- 学到：加权叠加框架的扩展性——GIS 模型的模块化思想。

## 3.5 怎么读结果

- **grid_data.csv**：每行一个 444m×444m 像元。用 Excel 筛选 risk_level=5 的行数占比，对照 fig1 的红色区域面积——数值与图像互证。
- **fig2**（因子得分图）：看哪个因子在全域普遍得分高——土壤湿度高的区域就是"先天不足"。
- **fig5**（转移路线）：检查有没有聚落匹配到很远的避难所——为什么？（低风险避难所分布不均）
- **evacuation_plans.json**：转移时长超过 2 小时的聚落是真正的隐患——泥石流预警时间可能只有 15 分钟。

## 3.6 思考题

1. AHP 权重来自专家主观打分。怎么验证这组权重靠不靠谱？（提示：历史灾害点回验）
2. 高程是"反向因子"的假设一定对吗？高海拔是不是也可能是无人区导致数据稀疏？
3. 欧氏距离算转移路程忽略了山路盘绕（实际路程可能是直线 3 倍）。这会让转移时长低估多少？
4. 密钥材料写在源码里，这种"加密"防得住谁、防不住谁？

| 因子标准化/反向因子 | 量纲归一到 0~1 / 数值越大越安全 |
| AES-256-CBC | 对称加密算法（密钥双方相同） |
| HMAC | 带密钥的哈希签名，防篡改 |
| 设备指纹 | MAC+主机名哈希出的机器身份证 |
| utf-8-sig | 带 BOM 的编码，Excel 打开中文 CSV 不乱码 |
| BoundaryNorm | matplotlib 把连续值映射到离散色阶的工具 |
